# Scope and source review

The stage-89 source remains exact. This stage changes harness placement and
diagnostic scheduling, and prepares the existing actual integration for the two
explicit storage roots. It does not change device contracts, PAT semantics,
source image contents, the worker, the matrix, reducer or application oracle.

The original fourteen-scope diagnostic packing is **failed**. Four scopes have
complete passing receipts for 28 distinct methods. The fifth received SIGKILL at
41.5 seconds while running its fourth method, with no final child receipt. Its
40-second CPU limit is a possible cause; the original launcher did not retain
CPU usage. The raw fixtures, source copy, logs, original owner-file identities and
verified acquired bytes remain intact. They are not opened as runtime databases
again. The three printed `ok` lines from that incomplete scope do not enter the
certified passing count.

The revised diagnostic profile keeps the exact child and test methods and runs
the remaining 43 identities individually. It explicitly increases aggregate
diagnostic budget while preserving each process's 60-second wall, 40-second CPU,
512 MiB memory, 128-FD, 16 MiB file and 256 MiB scratch bounds. Only complete
passing receipts can join the earlier 28. This is semantic control evidence,
not a pass for the original packing or a product throughput claim. Direct-child
CPU deltas are now observed in the parent.

The actual integration preserves its original combined scope: all thirty cases,
real reduction and vault import, catalog activation, one simulated GPIO effect,
original-key replay, configuration-drift refusal and cold vault/bridge history.
Its fixture inherits the original test method and changes only setup to create
the split supervisor. Five expected parent SQLite opens fit the unchanged maximum
of six. The child explicitly installs the declared 16 MiB inherited file cap.
The worker still has 60 seconds and its parent 180 seconds. No fixture splitting
applies to that run.

The native scan allowlist now includes exactly the control root, bulk root and
the original attempt beneath bulk. Admission scans control first and deducts its
logical file/byte usage from the bulk scan budget. The original native image and
sealed-memory checks stay exact. Capture holds the original control owner, bulk
owner, marker and selected writer lease; paths and object identities must agree
with the version-3 ledger. Copied evidence is never used as an equivalent mounted
storage authority.

The prepared actual audit retains the original full byte, implementation-identity,
publication, catalog and single-effect joins and adds the binding checks. It opens
only four parent databases in immutable read-only mode after acquiring owner and
writer files; no worker-case database is opened. Counts and signatures are not
substitutes for the thirty-case semantic reducer, which must execute in the
original scope. Audit assertions are evidence only after the audit runs.

Remaining requirements include a complete filesystem namespace, temporary-file
confinement, capacity checks before recovery writes, quotas covering every writer
and metadata/open-unlinked storage, and backed control continuations.
The directory-binding candidate supplies none of those capacity guarantees.
Actual device, driver and hub providers, persistent endpoint PATs, learning,
microscope commissioning and complete Harness/scenario integration remain required.
Review is by the primary agent; no independent review is claimed.
