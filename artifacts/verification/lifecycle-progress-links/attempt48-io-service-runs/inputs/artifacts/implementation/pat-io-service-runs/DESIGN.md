# Durable logical I/O qualification runs

This stage connects the [authority-owned configuration](../pat-io-service-authority/results/README.md) to immutable logical run reservations. It is an isolated host-library step toward prompt-to-PAT qualification and reuse. It does not launch a worker, claim that a reservation executed, install public services or promote a candidate.

A run is keyed by deployment, evaluator and logical run ID, matching the original supervisor key. Its intent binds the actual Journal authority, candidate digest and expected configuration receipt. The expected receipt is explicit: a new run cannot silently adopt a later configuration. Current administrators share the key; the receipt retains the first admitting principal. Changed intent under the same key conflicts. Current authorization is required for every lookup or replay.

Reservation uses two authority transactions around fresh preparation. The first checks exact replay before consulting source, runtime, active revision or remaining capacity. Fresh preparation uses the existing configuration service and actual installed resolver. The final transaction rechecks intent conflict, active configuration, all configured registrations and the exact selected descriptors in the prepared inputs. It atomically writes the request, configuration-history reference, reservation receipt and every original bundle document. The existing Journal clock-floor behavior remains unchanged. A pre-commit interruption leaves no partial reservation; a lost post-commit reply resolves through the original key.

Stored history uses an exact three-table schema, metadata digest anchor, bounded typed reads, contiguous global sequence and chained receipts. Each request is joined to its immutable configuration version and complete canonical bundle using the existing source-free parsers. The aggregate document-byte bound is checked before fetching document bodies. Missing documents, schema changes, temporary shadows, malformed records and inconsistent configuration references refuse without repair. These are trusted-store consistency checks, not protection against a coordinated rewrite of all records and anchors.

The default limits are 32 reservations and 8 MiB of accounted retained data; creation may lower either. Original input bounds remain 39 documents, each at most 64 KiB. Requests are at most 64 KiB, intents 2 KiB and receipts 4 KiB. No pruning, replacement, changed-key retry or capacity widening is added. Encoded data accounting is not an aggregate filesystem quota, SQLite allocation bound or hard latency guarantee. No current binding/source/permission result is cached across new reservations.

The reservation is a durable input commitment, not an execution claim. The separate supervisor ledger owns admission, process handles, writer leases, recovery and status. A host passes the retained request/bundle to that original supervisor. Public integration must still install and pin the supervisor authority, reconcile the handoff, and prevent a new or lost supervisor store from being mistaken for evidence that an old run never executed. A current configuration check at reservation is not a lease or an effect-time authorization. Historical replay retrieves the original inputs; fresh execution still requires the supervisor's existing source validation. Promotion must independently check current configuration eligibility.

Twenty-nine new control methods cover exact replay after source/configuration/session changes, full input persistence, lost replies and rollback, concurrency, authorization, capacity and deliberate corrupt-state retention. They are split into 15- and 14-method scopes to keep each raw tree under the existing 16 MiB control ceiling. Their only SQL opens are private compact runtime fixtures, at most four per method and 36/30 in the two scopes; no subprocess or network is allowed. The stored complete bundle is about 500 KiB in the existing fixture, so one combined control tree would exceed that ceiling.

One actual worker method commits configuration, reopens the authority, reserves the complete run, then uses the unchanged original supervisor and independent 30-case group reader. After completion it reopens the authority again, changes configuration, resolves the old reservation without replanning, and replays the same supervisor attempt without a second worker. Nine exact parent database opens are allowed: three runtime openings and three original supervisor openings. The source authority has zero effects/claims. The inherited 249 methods run with the expanded eight-file supervisor source identity; all old test bytes and deadlines remain unchanged. No hardware, emulator, acquired controller, live inference/service or adjacent Harness checkout is used. Primary-agent review only.
