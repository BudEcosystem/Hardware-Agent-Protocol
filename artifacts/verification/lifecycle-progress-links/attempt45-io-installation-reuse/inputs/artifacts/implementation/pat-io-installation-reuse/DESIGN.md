# Bounded reuse of pure installation normalization

This candidate starts from the [uninstrumented recovery source](../pat-io-supervision-recovery/implementation01/index.json). The [diagnostic profiles](../pat-io-supervision-profile/RESULTS.json) observed repeated pure normalization; they did not establish the cause of earlier nominal deadline failures. No diagnostic signal handler enters this candidate.

Only `hms/synthetic_io_installation.py` changes in production. The original semantic body is extracted without an AST change. Every call still bounds and canonicalizes its original input, rejects floats before canonicalization can erase their distinction, detaches the JSON, checks the closed profile and recomputes the installed driver source digest. Previously validated exact canonical input may reuse an immutable normalized tree under unchanged selected validation dependencies. The eight-entry LRU retains at most 512 KiB of keys plus eight bounded frozen trees. Each result is detached. This is neither an RSS limit nor an aggregate disk quota.

The preceding proposal mentioned retaining bytes. This candidate retains canonical byte keys and frozen builtin tuples for normalized results, avoiding a second encoding on a cold call. Source and structural bounds already restrict accepted JSON trees. No caller-owned mutable container enters the memo. Trusted configuration snapshots additionally support immutable sets of exact strings. Failed validation never publishes a result. The dependency guard runs before lookup and again before publication; changes clear only the expendable pure memo.

Selected module function/code/default/closure identities, normalization constants, topology and generation validator identities, schemas, validator iteration/type/format machinery and keyword callables are checked conservatively. This is not full Python-process attestation or a guarantee against arbitrary concurrent mutation of trusted private internals. Runtime configuration is versioned source/schema or validator replacement. In-place schema mutation disables this memo but retains the original lower-level schema snapshot behavior; no new revalidation guarantee is claimed for that unsupported operation. A source change during a call is detected on the next call; the source scan has the original timing semantics.

The memo contains static installation declarations, including initial generation declarations. It never caches current authority, permissions, bindings, generations, sessions, clocks, device effects or receipts. Those remain subject to their existing live checks. No deadline, effect, protocol, storage, source verification or tree-scan limit changes.

Fourteen new pure tests cover warm reuse with fresh source checks; nested mutation isolation; float/custom-value/custom-key rejection; source/helper/validator/configuration changes; changes during validation; private schema/keyword bypass; fixed entry and byte limits; noncanonical carriers and malformed/oversized JSON; absence of authority/provider/clock access; and concurrent detached results. Test-only profiling observes original functions without replacing guarded dependencies. The unchanged 171 control tests run with these fourteen, followed by the same nine separate process selections. SQL, launch and acquisition allowances remain those of the original harnesses. Every attempt and failure is retained; new fixtures do not repair old ledgers.

Review and execution are by the primary agent; no independent review is claimed. No physical ports, MCU/emulator, acquired controller, live inference/service or adjacent Harness checkout is used. Passing simulations would leave the full HMS, persistent applications, PAT learning, hard quotas, public qualification and actual device/driver/hub providers unfinished.
