# One static proof per installation instance build

The [current worker diagnostic](../pat-io-catalog-worker-profile/README.md) observes repeated pure definition construction. The original builder derives a complete resource proof for every action through `handler_details`, then derives the same instance proof again for the final binding. The proof already includes all actions of that instance and depends only on the provided topology and generation document.

The candidate changes only `hms/synthetic_io_installation.py` in production. An internal detail helper returns both the details and the freshly derived proof. The definition builder retains that proof only while building one instance's actions, then uses it for the final binding. The public `handler_details` entry always requests a new proof. No object survives the definition-building call, no authority/database state is cached, and no new caller-supplied proof ingress is introduced through a public function.

The first action still derives the proof at the original point, before its type bundle is assembled. Every action still resolves its handler, consumer, physical properties and expanded claims. The original complete type-bundle validator still runs. These pure helpers do not mutate the input document; all live resource, binding, source-identity, permission, session, operation and effect checks remain in their existing callers. Concurrent mutation of a trusted input document during a pure build remains unsupported.

Seven new controls compare exact canonical bundles, bindings and proofs with the original builder retained verbatim as a test reference, exercise multiple actions, changed generations between calls, mutation isolation, invalid proof inputs, public handler freshness and loaded-function purity. Derivation counts are observed without replacing proof or validation functions. The existing 14 normalization controls also run, because this module participates in their dependency identity. A separate full catalog integration uses the unchanged process method and original limits.

Start from the uninstrumented recorded-catalog source04; do not carry the diagnostic signal handler. Keep all prior failures immutable. Count reduction is not a timing guarantee; a fresh complete integration must still satisfy the original 60-second worker and 180-second parent limits, full 30-case matrix and all storage/effect limits.
