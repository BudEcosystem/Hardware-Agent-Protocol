# Independent outcomes for the complete finite group

The [preceding stage](../pat-io-encoding/results/README.md) completed both full
synthetic groups. Capture alone does not prove the expected responses. This
candidate connects all existing complete fixed-challenge readers and adds the
missing nominal completion composition around the replay/conflict history.

Trusted setup runs before the worker. It validates the complete original matrix,
requires an explicit initial authority revision and grants, prepares static
contracts, declares every fault/change plan, and snapshots implementation inputs.
Each case is a separate bounded document. The test harness retains these inputs
before invoking the unchanged group worker. This logical setup ordering is not
authenticated deployment or process/run attestation.

The independent reader receives a bounded byte archive and separately supplied
setup. It imports no compiler, planner, worker, runtime or setup module. It checks
canonical records, reference hashes, exact input/case association, required case
inventory, every fixed semantic response, nominal completion with replay/conflict,
and static parameter/context refusals. Completion of the candidate is distinct
from correct cancellation in a fault challenge. Missing, contradictory or
unresolved histories cannot produce a successful inspection.

The reader recomputes record, operation, tick and byte accounting across all
cases. Closed state bytes and zero-length ownership files must have the expected
inventory/layout; they are not interpreted as physical-effect authority. It checks
compiler/source identifiers against separate setup, without claiming process
identity attestation. Every input archive file must be consumed. Inspection
outputs remain separate bounded carriers and consume the existing derived-byte
and record ceilings.

The initial nine pure boundary/setup methods and both complete original group methods
were selected. The latter retain their original assertions, then inspect fresh output
with file, SQL and clock access forbidden. Every checker family's dispatch count
is asserted. Forged case ordering, success claims and compiler identity must
refuse before semantic evaluation. The original 60s capture and 180s parent
deadlines, 16MiB raw scratch and every original resource ceiling remain.

The [correction history](CORRECTION.md) retains two wrapper-format failures, a
pre-start launcher refusal and three fresh deadline failures. The latest candidate
has eleven focused pure methods plus the original 96 checks. An additional pure
test runs the unchanged complete source01 archive against the corrected reader,
using its separately retained pre-run setup. It also rejects false aggregate
accounting, an unreported file, a forged nominal report and changed trusted
authority. All 3972 subject/setup files are immutable acquired inputs. This
historical inspection is separate from acceptance of a fresh current group.

Source04 passes all 107 selected pure methods and the retained-history method.
Its fresh GPIO capture stops after 24 cases at the unchanged deadline, before
inspection. The active case retains a running parent despite its failed child
and canceled receipt; no state is rewritten to claim settlement. The prepared
source04 PWM harness is unexecuted. See the [complete results](results/README.md).

No passing result from this stage may set qualification, physical measurement,
