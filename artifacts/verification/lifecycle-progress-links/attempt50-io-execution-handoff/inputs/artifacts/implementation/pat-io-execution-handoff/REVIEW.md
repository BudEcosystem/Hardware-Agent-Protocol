# Review of the handoff boundary

Primary-agent review only. The frozen source and test-only extension are indexed separately. This review does not claim an independent second reviewer or physical-device validation.

The new ledger profile separates code identity from durable execution-store identity. Creation generates a fresh store ID; reopening requires that exact identity. Bounded metadata and the complete dedicated schema are checked before records are used. Legacy behavior is preserved by expanding the new metadata hooks and SQL constants and comparing the complete legacy abstract syntax tree with the preceding source. The new supervisor reuses the original process, ownership and recovery implementation.

The Journal stores a mount and a bounded receipt chain. Each receipt joins the source authority and deployment, reservation, request and actual supervisor attempt. The first lookup is historical: it validates retained history and current administrative access without rebuilding inputs from a changed source environment. A new admission additionally checks current configuration, installed descriptors and source identities. Only the creating invocation may launch after committing the association. Recovery and association reconciliation preserve the original attempt and never silently resume it.

The lock order is explicit. The supervisor execution lock serializes new admissions. A Journal transaction can read the supervisor ledger; a ledger transaction does not enter the Journal. Execution-store calls from an existing Journal transaction refuse. The association is the admission decision for this isolated qualification worker, not a continuing lease for effects on a physical device. Physical providers still need their own effect-time checks and local response behavior.

The first 32 handoff controls exercise individual runs, corruption, interruption, authorization and concurrency. Review identified that these did not demonstrate a chain spanning different run identities. The test-only extension adds five methods for two distinct attempts, exact chain links, reopen replay and well-formed history forgeries. All prior 252 project files, including production code and inherited tests, remain unchanged. The extension's launch boundaries are substituted; its successful replay result does not stand in for the failed actual-worker replay test.

The real worker persists the association before launch, but its original deadline prevents complete matrix inspection and post-drift replay. The compatibility batch's outer deadline also prevents complete child-origin and result receipts. Those gaps remain explicit. Source-free readers inspect only terminal retained state; transaction-bearing or incomplete fixtures are preserved without recovery, and unknown totals remain unknown.

This design does not provide cross-database atomic commit, coordinated-rollback protection, aggregate filesystem quotas, protected compute capacity or general multi-supervisor routing. It does not mount public tools or add actual device/driver/hub providers. The [next boundary](NEXT.md) keeps serialized evidence import, current eligibility, promotion and the complete prompt-to-PAT application lifecycle in scope.
