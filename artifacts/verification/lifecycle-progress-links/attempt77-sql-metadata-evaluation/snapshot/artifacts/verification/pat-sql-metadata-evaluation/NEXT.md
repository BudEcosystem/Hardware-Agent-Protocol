The combined metadata candidate is rejected by the fixed performance screen.
Keep it uninstalled and retain its original results. Do not repeat it for a
different timing outcome or merge the row-count guard into cell aggregation.

The [retained research and observation](../../../research/host-contract/sqlite-statement-cache/README.md)
support a different bounded experiment: run unchanged capture methods over the
complete closed authority/board inventories in fresh memory databases, comparing
the observed 128-statement default with one predeclared finite alternative.
Use the full per-connection SQL working set, not separate one-table connections.
Retain source/SQLite pins, all table queries and exact page bytes/refusals.

Measure compilation using a declared diagnostic observation independently of
uninstrumented paired timing. Record actual preparation observations rather than
equating every `execute` with a fresh prepare. Include cold/warm capture, schema
changes, changed parameter values and changed rows between calls. Reuse compiled
SQL only; never cache data, authorizations, resource bindings or outcome claims.

SQL before guard entry, denial within the guard, swallowed-denial detection,
guard replacement/removal, restoration after exceptions and schema-triggered
recompilation. Preserve the original owner/transaction checks. Account for cache
memory and cursor lifetime; a count limit is not a byte guarantee. Inspect the
matching connection/cursor implementation before relying on undocumented details.

and application gates still apply with their original limits. Public service
