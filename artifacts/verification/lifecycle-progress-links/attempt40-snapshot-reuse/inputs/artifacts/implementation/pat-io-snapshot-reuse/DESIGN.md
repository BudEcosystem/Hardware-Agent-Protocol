# Reuse pure bounded topology snapshots

The [current profile](../pat-io-page-encoding/PROFILE-ANALYSIS.json) identifies
repeated topology snapshots, installation processing and canonical encoding.
The existing eight-entry schema memo already identifies successful checks by
canonical carrier bytes and the exact validator object. This candidate retains
an immutable frozen tree with that success, then reconstructs detached built-in
containers without caller copy hooks.

Canonical byte inputs can match an already validated byte key directly. Every
other byte input follows the original bounded parser, strict scalar check and
canonical encoder. Object inputs still canonicalize and reject unsupported
original scalar types before lookup, so integral floats cannot inherit an integer
snapshot. Oversized bytes are rejected by the original parser before key lookup.
Keys retain at most eight bounded carriers (512KiB); associated frozen trees are
bounded by those carriers' original depth/node limits. This is not a total-RSS
quota claim. Replacing a validator invalidates its cached result.

Every graph, footprint, generation, dependency and authority-dependent semantic
check remains outside the cache and executes again. Cached trees cannot be
mutated through returned dictionaries/lists or through subsequent caller input.
No SQL query, current source check, admission decision, mutable generation or
permission result is cached. The installation normalizer also reuses its first
canonical encoding after the original strict float scan, preserving source checks
and all semantic validation.

One earlier encoding test is renamed and updated to require zero encodings for
the now-warm canonical byte carrier; its exact output/detachment assertions stay.
All original group, cutoff, semantic, schema and topology checks remain required.
No deadline, challenge, protocol, effect or storage limit changes. Full fresh
capture/inspection, process/run attestation, aggregate enforcement and public
qualification remain separate gates. Live HMS and the adjacent Harness stay
unchanged; no physical/MCU, inference or external-controller execution is allowed.

The [results](results/README.md) now pass 132 distinct methods, including complete
fresh GPIO/PWM capture and independent inspection for two constant single-step
candidates. Source02 only corrects a new test's graph-check inventory; production
matches source01. Original limits remain, and earlier failures stay retained.
The remaining qualification gates are trusted configuration/process/run
association, hard aggregate enforcement and supervised public service integration.
