# Source and data coverage

All inputs come from the sealed current copy-boundary packet. [source-pins.json](source-pins.json) identifies eleven exact original files. The nine small source/map/metadata/result files are frozen under `source-snapshots/`; the 1,162,185-byte LTRANS assembly and 825,252-byte WPA inline report remain referenced by exact immutable path/hash. All 640 parent index entries were revalidated before analysis. No parent or public file was modified.

Complete C reading in this continuation covers `standing.c`1–749 and `endpoint.c`1–630, and both complete endpoint/standing headers. This includes all callbacks, observation/feedback/loss functions, lifecycle mutations, finite admission and writers, and finite continued service—not only the changed-looking expressions. These are local implementation primary sources. No additional online/compiler-source acquisition was needed for a source-only proposal; existing GCC qualification behavior remains subject to generated-code verification.

The three generated bodies were mechanically enumerated in full to obtain instructions, literal operands, nominal widths, call sites and exact token-repeat joins. `extracts/*.instructions.tsv` retain those bounded instruction inventories. This does **not** claim a semantic review of every instruction in all 8,604 instructions. Human semantic reading is precisely scoped in [coverage.json](coverage.json): complete small encoder/decoder bodies; observation-commit/age-min repetitions; standing-handler prologue and OPEN/RESUME timestamp regions; finite-handler prologue through the standing-call branch; and HELLO/control timestamp regions. WPA6435–6638 was read completely for actual inlining decisions. Map430–790 was read completely for allocated bodies/helpers/libraries and main storage sections; aggregate section arithmetic was additionally parsed from the complete map text. Exact range bytes/hashes are retained.

`body-observations.json` contains mechanically discovered repeats beyond the specifically interpreted examples in ANALYSIS. Uninterpreted smaller repeats are not promoted into source proposals or attributed savings. Each interpreted span was read with its surrounding instructions and corresponding complete C function. The complete retention specification and parent result note were read and pinned; the map joins all thirty function symbols and nine exact storage sizes. The full backend `.su` is pinned for traceability; this packet neither derives nor claims a combined call graph/stack maximum from it.

[measure.py](measure.py) uses only Python standard-library file reads, text parsing, hashing and JSON writes in this new design directory. It imports no candidate code, has no subprocess/network/device access and does not execute any target or inspection tool. Its observed run passed the three body width/map joins, all recorded exact token-repeat comparisons and aggregate failed-map arithmetic. Existing `body-observations.json` is an asserted input to that reproduction, so this is a consistency join rather than an independent repetition-discovery algorithm.

No LTRANS object or final ELF is retained in the current failed build; only the twelve original compile objects are available. The map's LTRANS object pathname is evidence of a link input that existed then, not evidence that it exists now. Accordingly the packet distinguishes matching instruction text from unobserved machine-byte identity. No relocation, runtime-cycle, bus-latency, deadline-latency or physical evidence claim is made.

The parent results and current proposal are deliberately separate: the former demonstrate native control success and an AVR link overflow; the latter is an unimplemented plan with unknown savings. Neither substitutes finite OP/ARM replay for persistent local control or claims host ledger/PAT completion.
