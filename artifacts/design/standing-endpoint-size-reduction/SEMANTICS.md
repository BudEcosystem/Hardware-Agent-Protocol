# Equivalence obligations for the proposed implementation

These are source-level proof rules for the next diff, not a proof of nonexistent candidate code. The public machine state, wire format and callback trace remain the specification. A source change is acceptable only when its actual implementation satisfies these rules and the controls in CONTROLS.

**Encoded values.** For bytes `b[0..7]`, define `E(b)=sum(b[i]*256^(7-i))`. This is a bijection onto the complete unsigned64 domain. Lexicographic unsigned-byte comparison has the same sign as comparing E: at the first differing byte, that byte's weighted difference exceeds the maximum contribution of all following bytes. This justifies a comparison kernel without constraining upper bytes. It does not define ABSENT behavior; each caller keeps its explicit check for E=UINT64_MAX. Existing direct encoded comparisons already using `memcmp` need no rewrite.

**Captured values and predicates.** A pointer to an existing native snapshot denotes the same uint64 value that the old by-value expression used, provided no write/callback occurs between its original capture and the helper's read. Helpers contain no callbacks or state writes. Each migration must identify that capture, not merely find matching variable names. In particular finite admission's four timestamps remain captured before `describe`; standing dispatch's `before` and `cutoff` remain captured before driver entry. Later fresh `now_tick` reads occur after the same clock callback. Replacing a saved value with a later reload is forbidden even if a normal test fixture leaves the value unchanged.

For unsigned `a,b`, a helper evaluating `(a-b) < k` must use subtraction modulo2^64 exactly like the old C expression. If the old expression first tests `a>=b`, retain the test and its short-circuit order; then the subtraction is also the mathematical nonnegative difference. It is not valid to add an order check to a site that deliberately evaluates a different expression, remove an overflow check because a typical lease is small, use signed comparison for high-bit values, or replace `<` by `<=`. Limit arguments retain their existing16/32-bit values; they do not truncate the timestamps. All error/status-producing predicates stay in their original order.

**Saturating minimum.** Let `M=UINT64_MAX`. The proposed cutoff leaf must compute exactly `c'=min(c, x<M-d ? x+d : M)` for the original nonnegative delta. In the first arm `x+d<M`, so native addition cannot wrap; in the second the original deliberately chooses M. At `x=M-d`, the chosen value is M, not0. For `d=0`, x=M also yields M. Taking the minimum is associative as a numeric result, but calls/reads are not freely reorderable: retain observation0, observation1, then on-time allowance with the original intervening early returns. `cutoff-window+1` keeps its existing `cutoff<=window ->0` guard. No input sentinel policy is inferred from the algebra.

**Serialization.** Each scalar encoding first captures the old source value and writes its bytes in the original order. Thus it remains correct even when an earlier surrounding write has changed another subsequently read field: the helper must not take a new whole-struct snapshot. The38-byte context group and21-byte finite tail consist of exactly the existing scalar writes/copy, with the same sequence and offsets relative to their new destination base. Changing a group into a raw native-struct copy is not equivalent. The accepted-observation helper is entered only where the old four copies began; validation, duplicate handling and failure side effects happen first, and the channel ready flag remains after the common copies. No retained array gains a new alias/lifetime assumption.

**Phase separation.** Replacing a contiguous straight source phase by an ordinary function call preserves its state transition only if it receives the same live values, performs the same reads/writes/callbacks in order and returns the same status at the same continuation. It cannot perform deferred work on another poll, coalesce two driver phases, introduce an extra fresh-clock sample, or allocate a second report visible across callbacks. Preserving this source transition says nothing about stack/flash: those must be checked on the actual generated caller+callee path, including argument storage and interrupt preemption.

**Authority and evidence.** The shared numeric/wire helpers are pure with respect to endpoint/controller authority. They cannot claim resources, advance revision/counters, dispatch I/O, release claims or turn an unknown report into a known result. Finite admission and standing OPEN still commit all claims only after validation; pending activation identity still precedes actual driver entry; loss remains independent of the bounded activation ledger. A representation optimization may not turn interrupted feedback into cancellation, ACK unresolved loss, reuse the private handoff alias as public quiescence, or repair a latched clock/driver fault. Those invariants are preserved by leaving their transition code and callback boundaries intact, then verifying complete traces rather than only final numeric outputs.
