# Proposed standing deployment contract

Everything below is a proposed new profile. The current finite endpoint and bound-sequence PAT semantics are not changed by this document.

## Identity and immutable version

The host retains a stable application identity and immutable intent revision, the selected PAT artifact/compiler/evaluation/decision, full dependency closure, exact bound parameters and resources, owner authority, outage policy and explicit output/evidence limits. A changed user requirement or changed executable/configuration bytes creates a new revision. Friendly names are not mutable execution pointers.

The durable host deployment key is `(principal, authority deployment, replay namespace, deploymentKey)`. It maps to one endpoint activation namespace `(incarnation, qualified boot epoch, standing_number)`. `standing_number:u32` is positive, strictly increasing and never reused within the boot; its high-water mark survives retirement until qualified boot change. It is separate from the existing finite OP call high-water mark. A complete `deployment_digest:[32]` pins the immutable host mapping; it is not authentication. The installed trusted gateway verifies that mapping, as it already does for compact OPs.

The retained record also pins the original control generation/context handle, installed kernel ID, exact 32-byte configuration, resource mask and admitted fences, two expected input epochs, initial absolute lease and evidence mode. An exact duplicate OPEN compares the complete immutable packet and returns the current deployment snapshot. Different compact fields under the same standing number conflict even if the caller supplies the same digest. Retired numbers return OLD_OR_FORGOTTEN, never permission to reactivate. The current standing number equals the high-water value only while the tagged slot holds a standing record; finite OP use must preserve that historical high-water without presenting it as a current standing owner.

Control mutations have a separate positive non-wrapping mutation sequence, expected lifecycle revision and exact typed body. A retained exact retry is recognized before checking today's revision and returns current status plus the accepted mutation identity without reapplying effects; changed bytes under that sequence conflict. The last accepted request's expected revision is retained independently of the current revision, which may advance after asynchronous loss. An older sequence whose complete body is no longer retained returns OLD_OR_FORGOTTEN and cannot mutate. A new mutation must be the expected next sequence and match the current lifecycle revision. Rejected mutations do not consume sequence or create a local refusal-history promise. The host records mutations durably before handoff. Lifecycle revision covers control/state transitions; sample and pending-feedback updates have their own identities/states. Frame sequence remains transport correlation only.

## Start, renewal and revision

OPEN validates the whole static contract while no finite OP or standing record occupies the local slot, checks current authority/platform and expected input epochs against installed source bindings, and atomically reserves every resource/fence before acquisition. It produces PREPARED with no ordinary output and starts bounded acquisition under those owned resources; it does not depend on an unowned bus read. A separate START mutation activates within the current prepared lease after fresh STATUS/host checks and locally rechecks both fresh inputs and ownership immediately before possible output. Initial START uses OPEN's original initial lease; START after RESUME uses that explicitly prepared new lease. PREPARED expiry excludes ordinary output and enters the installed settlement path while retaining ownership and the record until eligible RETIRE. Acquisition may itself perform declared bus effects, so an unstarted controller is not proof of zero device interaction. The host must durably retain the deployment and activation namespace before requesting START.

The standing lease is an absolute exclusive boot-local `u64` tick. The first profile uses the same installed upper horizon of at most 60,000 ms, but a separate deployment renewal operation and state. RENEW is valid only while ACTIVE, before the current deadline, with exact owner/version, fresh authority and a qualified clock. Its new deadline must be later than the current deadline and within the installed horizon from now; checked arithmetic rejects overflow. A duplicate or delayed old renewal cannot shorten or extend the current deadline. Reaching the cutoff latches loss/draining before another ordinary output. A late RENEW cannot revive it.

Renewal extends only this deployment's current authority interval. It does not change configuration, clear observation gaps, reset activation/effect counters, erase evidence, free resource claims or replenish a full transition ledger. Existing finite ARM never renews a standing deployment, and a standing renewal never changes an existing finite OP. The new wire/profile must expose separate finite and standing eligibility instead of reinterpreting the old HELLO INHIBITED flag.

SUSPEND prevents further ordinary activations and invokes the installed bounded drain/loss policy. Only confirmed quiescence yields SUSPENDED_QUIESCENT. In this first profile suspension retains the deployment's resource reservation and fences; quiescence knowledge does not transfer ownership. Before RESUME the trusted host durably collects the loss/quiescence summary and complete ordinary ledger, and its ACK watermark must equal activation high-water. RESUME is allowed only for a resumable, undisputed cause with unchanged valid context, the same complete owned resources and source epochs, no unresolved effect and a new lease. It moves to PREPARED, clears only the exported episode/witness and freshness-ready flags, and starts fresh bounded acquisition. A subsequent START permits ordinary output after fresh local and host checks. Activation numbers, ACK history, cumulative accounting and original OPEN bytes never reset. A reset, revoke, manual override, sensor epoch discontinuity or disputed outcome requires reconciliation/new binding as appropriate and cannot be bypassed with RESUME. STOPPED_QUIESCENT and FAULT_UNKNOWN cannot resume. Yielding resources to another owner requires STOP and retirement; resume cannot reacquire a partially lost set implicitly.

STOP is terminal intent. Its acknowledgment means that the request was accepted, not that outputs stopped. It enters DRAINING, then STOPPED_QUIESCENT only after the installed stop and aggregate resource-quiescence predicate succeeds. A terminal/disputed outcome retains its identity and evidence. This first standing profile has one aggregate witness and no partial release; known quiescence and ownership are separate masks. RETIRE alone releases the reservation after terminal quiescence, host durable collection of the complete retained record, and resolution of required outcomes; retirement preserves number/fence floors. There is no timer/LRU eviction. Version replacement is stop/drain/reconcile/retire followed by a new standing number and digest; first-profile hot replacement is unsupported.

## Triggers and fresh local observations

The first kernel has two scalar inputs: control demand (for example temperature) and independent response feedback (for example tachometer/rotation). Their installed schemas define source identity, units, scaling, range, acquisition clock, calibration and producer epoch. An observation record contains a signed 32-bit value, acquisition tick, source-local non-wrapping sequence, source epoch and explicit quality/continuity state. A compact source epoch is a non-reused local mapping within the qualified endpoint boot, backed by the full host binding; truncating or hashing a larger producer identity into it is forbidden. A provider unable to establish that mapping/continuity is unsupported. Re-reading a cached value does not refresh its acquisition tick or sequence.

The scheduler polls each installed nonblocking acquisition state machine at the configured bounded period. It evaluates at most one controller decision per foreground service opportunity, using actual acquisition times and a fresh qualified clock. A per-observation pending-evaluation flag is set only by a newly accepted sample and cleared by bounded evaluation; duplicate publication cannot invent a trigger. An evaluation with no output change is not an output activation; its sample identity still determines which observation was evaluated. Missed periods do not cause an unbounded catch-up burst. The profile uses latest-state semantics, not an edge queue: it may skip intermediate sampling opportunities only where the installed acquisition contract declares that behavior and the gap remains within its freshness/continuity bound. A dropped required event or unknown sequence gap is a fault; freshness is not inferred from eventual UART delivery.

Before an ordinary output transition, require the exact producer epochs, strictly advancing accepted sequences, good quality, no unexplained regression/gap, valid ranges and `acquired_tick <= now`, with age strictly below the configured maximum. A duplicate returns the existing local observation state without triggering a second transition. Invalid candidates set fault/quality state without lowering the accepted sequence, overwriting its retained value/time, or replacing the pinned epoch. A new epoch cannot be treated as the next sequence. Both channel epochs are pinned from OPEN; a restart/reconfiguration stops admission and invalidates that binding.

The hysteresis kernel compares a demand input to lower/upper thresholds, enforces minimum dwell and installed output/rate bounds, and checks feedback within an explicit response window. Desired command, controller readback and independent measured response remain different evidence. A fan register reading cannot establish rotation, cooling or temperature improvement. The optional ineffective-response criterion uses the pinned temperature baseline/minimum drop and response window; its bounded, explicit failure state generates an exception for the host/agent. It does not silently change thresholds or select another strategy.

Ordinary activations get `(incarnation, boot, standing_number, activation_number)` before the I/O boundary. The counter is non-wrapping, and possible output is recorded before dispatch. Any installed native output queue must retain that identity/fence and obey the current absolute cutoff at the actual I/O boundary. One activation may be in progress; another cannot overwrite its pending outcome. Acquisition alone is not an ordinary output transition and cannot consume or fabricate an output receipt.

## Bounded feedback and evidence retention

The target proposal retains two unacknowledged transition/evidence records. Each records its activation number, dispatch time, the triggering demand sample/age, later feedback sample/time, previous/requested output, evidence/quality state and reason. Pending feedback occupies its slot; completion does not free it. A host ACK is accepted only for a contiguous terminal, known, undisputed activation prefix the host has durably committed, with exact deployment identity. It cannot skip pending/unknown/disputed entries. Allocations are contiguous and checked against wrap, so activation high-water minus acknowledged watermark equals the retained ledger count. ACK frees those bounded evidence slots, never resource claims. Lost ACKs are resolved by exact retry/status, not by synthesizing replacement activation IDs.

The host reserves capacity for owed control records before START/renewal. Evidence-learning storage exhaustion must not consume the space required for loss handling and reconciliation. A missing/failed host commit cannot authorize ACK. The local controller may continue without the hub only while its unexpired lease, fresh inputs, installed effect limits and two-slot evidence capacity permit. When another ordinary transition would exceed the ledger, it enters the declared loss policy instead of overwriting evidence. Stable output supervision and independent local protection continue under their respective installed limits; the profile does not promise unlimited disconnected autonomy.

A sticky fault/loss record, separate ownership/quiescence masks, first-loss/cleanup/quiescence times and dedicated 22-byte aggregate witness exist outside the two ordinary ledger slots. At first loss, ordinary observations and controller state freeze for diagnosis. Bounded loss acquisition uses driver scratch and that witness, so a full ordinary ledger cannot block the installed bounded stop/loss response or be overwritten by it. Loss-response effects have their own installed envelope and uncertainty reporting. Failure to establish its postcondition leaves FAULT_UNKNOWN with claims retained. A stopped fan or an output value is not universally a quiescence proof; the installation defines the actual aggregate resource predicate. Clock failure leaves affected timestamps absent and requires independently qualified protection for any claimed physical response.

This small profile retains output-transition evidence and the latest input state, not every intermediate sample/evaluation. It must not label that a complete acquisition or learning trace. Qualification can retain the complete known synthetic input schedule and independent outcomes; physical learning that requires all samples needs a separately bounded, qualified observation/data-plane recorder or a richer endpoint profile. Missing trace coverage is explicit in the evaluation result and cannot be promoted into a broader observed-context claim.

The host's durable reservation of the boot/deployment namespace plus the endpoint's qualified boot reservation prevents activation identity reuse. It does not durably store every locally generated event. On power loss, volatile observations, in-flight records and even the exact consumed counter prefix may disappear. The host marks the possible unacknowledged suffix unknown and retains its resource/physical-history obligations. The new boot cannot replay that suffix or claim it never happened. Full offline event-journal recovery and irreversible dispensing/motion effects without sufficient outcome recovery are unsupported by this first profile.

## Loss and recovery matrix

| Event | Immediate local rule | What permits later ordinary work |
| --- | --- | --- |
| Hub/model unavailable | Continue only under current local lease, fresh inputs, output limits and free retained-record capacity; never call the model from the control loop | Reconnected authorized host reconciles the same deployment and records; renewal before expiry may preserve ACTIVE |
| Lease expiry or ledger exhausted | Latch ordinary inhibition, enter installed loss/drain path | Explicit quiescent recovery/resume policy or new deployment; late renewal alone is insufficient |
| Sensor stale, bad quality, gap or epoch change | No ordinary transition based on that input; sticky fault and installed response | Qualified source recovery plus explicit reconciliation/rebind when continuity was lost; not merely a newly fresh-looking value |
| Clock unqualified/regressed | Latch FAULT_UNKNOWN, no ordinary scheduling or invented timestamps | Qualified platform recovery/new boot and reconciliation; clock-failure stop service needs an independent qualified mechanism |
| USART/configuration ownership drift | RECONCILE and close affected transport admission; local loss servicing continues | Repair/commissioning and fresh binding; serial reconnect cannot clear it |
| Driver/PWM/timer/bus generation change | Reject ordinary work before incompatible effects and hold affected claims through drain | Quiescent lifecycle settlement, publication of new generations and requalification of the exact PAT dependency closure |
| Manual override or REVOKE | Inhibit first, advance control domain without wrap, drain according to installed policy | Local reconciliation and a new bound control domain; old messages cannot restore authority |
| Endpoint reset/history loss | Installed reset gate first; acquire a new qualified boot; no automatic program resume | Host queries/reconciles previous possible effects and binds a new activation namespace |
| Host restart | Recover durable owner/mutation/activation mappings; do not allocate replacements | Query exact existing deployment and receipts; a new host session alone does not reset remote state |
| Counter exhaustion | Inhibit before wrap and retain known/unknown history | Explicit quiescent retirement and qualified new namespace, never wrap-to-zero |

The sealed AVR adapter currently closes UART admission on clock failure. This design cannot claim STATUS/STOP wire availability under that failure until an independently timed degraded service path is implemented and qualified. Local loss/independent physical stop must not depend on the unavailable transport or model.
