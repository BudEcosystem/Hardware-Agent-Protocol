# Finite I/O supervisor adaptation

This isolated candidate adapts the previously reviewed fan supervisor to the
bounded I/O input bundle and complete group output. It preserves the original
ledger transaction/ownership transitions, writer lease, retained Popen/pidfd
signaling, interrupted-owner recovery and exact-key replay. The supervisor's
private request profile changes; existing fan ledger roots are not migrated or
reinterpreted. The full device/driver/hub and learning objective remains open.

The admission record contains the bounded header, external logical context,
input digest, group limits, implementation identities and supervisor identity.
Fresh admission snapshots the supplied byte mapping and rebuilds it against the
current setup implementation. Exact replay reads the durable original record
without fresh planning or requiring the input mapping again. Changed same-key
requests conflict. Logical run IDs never authorize signaling a stored PID.

Before launch intent can commit, the supervisor exclusively creates and fsyncs
the header and every fixed input/case file under private no-follow directories,
rereads the exact closure, and writes the launch envelope containing the actual
ledger-generated attempt ID. The child receives inherited directory/input/lease
FDs, checks those private objects, reloads the retained bundle, and reconstructs
the setup again before executing the original finite I/O group. The image now
includes the I/O endpoint scenario manifest and all seven selected dependencies.

The original parent deadline is the selected group's existing maximum wall time,
including child startup and fresh validation. The group's own wall guard remains
unchanged. Source image construction occurs before this launch deadline. TERM,
KILL, process settlement and lease recovery retain their previous logic. No
restart, rebind, replacement mutation key, state reset or case omission is added.

After quiescence, collection revalidates retained input bytes and checks the
worker's attempt/request/bundle/result association. It hashes every output file,
including closed database bytes and incomplete output, using ordered path/size/
content references under the original per-file, directory-depth, file-count and
20 MiB group-derived bounds. This is transport integrity, not case semantics.
The ledger keeps only its small receipt and closure digest; it never equates a
failed group, complete transport, or unknown effects with qualification.
Semantic qualification, hard aggregate quota and unresolved-effects flags remain
false/unknown as appropriate. Full independent group inspection is a later step
in the integration test, not a side effect of archive admission.

The existing 64 MiB attempt reservation, 256 MiB retained-root limit,32archives,
8,192 entries per attempt, bounded streams and stop/settlement grace are retained.
Reservation preflight now includes all input carriers alongside output and
control. Logical scans and RLIMIT_FSIZE are not enforced aggregate storage.
Trusted fixed service configuration and actual quota provisioning/verification
remain prerequisites for a public qualification service. Supplied configuration
metadata is not deployment attestation. Python network guards are not a sandbox.

The initial source adds five adapted supervisor modules and two test files to
the unchanged230-file I/O candidate. Primary-agent review covers every delta;
helpers remain usage-limited and no independent review is claimed. The first
harness selects149 prior pure methods plus11 new request/file-transport methods,
with no SQL or child spawn and the unchanged16MiB scratch bound. A separate new
process harness selects one actual GPIO integration method under the original
180s test-parent ceiling and60s supervisor/group ceilings. It allows only the
fixed supervised entry and the parent's exact private ledger SQLite pathname.
The child's pinned original code opens only synthetic case state.

The process harness acquires up to256MiB of raw test output so it can retain the
already-budgeted supervisor root (code image, input files, database, streams,
full group and inspection). This is a distinct supervisor integration acquisition
scope derived from its existing256MiB root limit, not a change to the pure/group
harness, per-carrier, group-derived, per-attempt or execution limits. Originals,
failed attempts and partial states are retained. No physical/MCU execution,
inference, acquired controller, live HMS or adjacent Harness work is involved.
