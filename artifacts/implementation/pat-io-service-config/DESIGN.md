# Trusted configuration for finite I/O qualification

This stage joins the [tested I/O supervisor](../pat-io-installation-reuse/results/README.md) to explicit service setup. It extends the [service plan](../../verification/pat-service-design/PLAN.md) and [review](../../verification/pat-service-review/README.md) for the implemented combined GPIO/PWM policy. The original fan configuration remains unchanged.

The closed configuration fixes deployment, evaluator ID, configuration revision, installation digest, initial synthetic registry revision, explicit semantic registrations, artifact-to-role assignments, four resource-challenge bindings, group limits and supervisor limits. It contains no command, import path, URL, callback, success assertion or caller-supplied implementation attestation. Registrations and assignments are normalized as sets. Configuration is bounded to the existing 64 KiB carrier; limits cannot exceed existing ceilings.

Trusted setup validates registrations against the current installation and installed primitive semantics, and derives a service pin from current compiler, driver, worker and supervisor identities. `io_services.py` is added to the supervisor source closure, so its bytes are included in the retained code image and supervisor identity. The only existing production edit is that closure addition. All other inherited production and test bytes remain unchanged.

`ConfiguredIoService` requires an externally supplied expected pin and retains detached immutable configuration/installation/pin bytes. Fresh preparation accepts only an artifact, logical run ID and new explicit trusted descriptor snapshots. It requires the complete configured descriptor inventory, validates binding/type/driver/installation/semantic associations, chooses only the configured artifact assignment and challenge bindings, and derives the existing trusted-authority document. The original full matrix, bundle and supervisor request builders run with configured limits. Their final identities must still match the pin. No descriptors or live authority observations are cached across runs.

The historical reader requires independently retained service pin, logical run ID and request digest. It checks configuration, request, input collection and limit associations without source reads or replanning. Rehashed replacement requests cannot satisfy the old external digest. This is structural replay validation; it does not independently establish live authorization, current configuration, process execution or qualification.

This API performs no SQL write, worker launch or catalog promotion. The expected pin is trusted input, not proof that an authority has durably installed it. A future authority configuration record must authorize installation, retain revision/pin changes, reconstruct this setup on reopen and obtain current descriptors from the installed resolver. Serialized evidence import and the existing evidence-integrity checks must precede promotion. Public mounting and actual aggregate storage enforcement remain required; filesystem accounting is not a quota.

Twenty-one new control tests exercise bounded parsing, exact primitive registrations and assignments, current-source pins and drift, fresh descriptor inventory/session changes, source-free anchored replay, mutation isolation, denied execution fields and absence of SQL/provider effects. One actual configured GPIO group uses the unchanged worker and independent outcome reader, retaining configuration, pin and request digest in the private fixture before supervisor construction. It checks exact replay before/after reopen and changed-key conflict. This test retention is not a production authority configuration store.

Run the unchanged 185 control tests plus the 21 new controls, the same nine existing process cases, and the configured process case. All source/harness inputs are frozen before project execution. Existing time, effect, source, file, stream and retention bounds remain. Every raw attempt and failure is preserved. No device port, MCU/emulator, acquired controller, live inference/service or adjacent Harness checkout is used. Primary-agent review only; independent review is not claimed. The full HMS goal remains active.
