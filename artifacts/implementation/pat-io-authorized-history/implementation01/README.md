# Independent authorized finite-I/O history composition

This isolated candidate joins the existing configuration/permission, PAT intent,
board, operation and parent checkers over retained original simulation captures.
It derives active pending-receipt outcomes from prior cancellation, temporal
limits, trusted invocation permission and due time, in that order. It compares
all claimed resource states, counters, terminal receipts, event transitions and
claim release through the independent components. Historical terminal receipts
cannot change when permission is later withdrawn. Unknown outcomes with already
terminal receipts reconcile without requiring new invocation authority.

The separately trusted setup and grant plan are inputs, not values inferred from
captured grants or provider reason strings. Immutable configuration, exact actor
bindings/sessions and fresh after-phase observations constrain the guard context.
The private board cause handoff accepts only the permission stops derived here;
unused cause entries refuse. The public board API still refuses this cause on
its own. The public configuration API preserves its active-withdrawal refusal.

Source preserves 5,049 inherited project/data files and changes only the two
independent readers to supply/consume this private validation handoff. Runtime,
provider, compiler, all inherited tests and all inherited fixture bytes remain
unchanged. Six actual active-withdrawal captures add 849 exact data copies plus
an index. Two new Python files provide the composed checker and 20 tests. There
are 5,903 project/data inputs. The selection combines those 20 methods with all
48 configuration and all 35 board regression methods: 103 pure tests. Positive
cases cover all six new captures and existing GPIO, PWM, reopen and sixteen-step
configuration captures. Attacks rehash page and inner receipt data and verify
refusal of fabricated stop causes, wrong precedence, rewritten completion,
suppressed stops, premature claim release, wrong output/ownership/counters,
false parent completion and stale guard context. Purity checks veto I/O/clock/SQL.

The input bounds remain 4,096 combined records/16 MiB/64 KiB documents and 2,048
ticks. The pure harness retains its original 180-second limit and 16 MiB scratch
limit. No runtime, SQL connection, physical device, MCU/emulator, live inference,
public service or acquired controller runs. This is an immutable single-actor
simulation profile with read permission retained during invocation withdrawal.
Pending unknown recovery stops, full read withdrawal, other failure causes,
auxiliary actors, intermediate sampling semantics, complete timing/fault coverage,
current compiler identity, aggregate enforcement and public qualification remain
unfinished. All full-attestation/outcome/qualification flags remain false.

Primary-agent source review only; helper accounts remain usage-limited. No live
