# Remaining integration work

This candidate supplies the isolated authority-vault catalog/admission boundary.
The project goal remains active. Final verification receipts describe which
controls and full integration scopes passed; earlier failures stay retained.

1. Integrate the selected Journal, vault, authority import, catalog and execution
   versions into the public runtime factory and authenticated tool service.
   Preparation must remain an installed service operation. Preserve original-key
   history, complete candidate inventory, bounded evidence acquisition and pure
   checks at business commit. Run the relevant existing service, transport and
   full runtime regressions on the integrated source.
2. Implement backed control-storage capacity and aggregate storage enforcement.
   Separate databases and page caps alone do not reserve the storage needed to
   finish already admitted operations. Validate full-disk behavior, hot-journal
   recovery, evidence-store unavailability and control completion under original
   ownership and recovery rules.
3. Add concrete providers for physical I/O, buses, driver lifecycle and the
   intelligence hub. Model shared pins, timers, DMA, buses, compute and storage
   with real ownership and dependency contracts. Driver replacement and hub
   restart must account for affected work and invalidate changed applicability.
4. Connect natural-language intent and observed context to typed candidate
   synthesis and explicit qualification policies. Route an applicable PAT
   deterministically; distinguish a new context from unavailable evidence,
   ambiguity, stale bindings and unresolved prior effects. Failed or missing
   qualification cannot be promoted into learned behavior.
5. Extend beyond the current single finite synthetic-I/O role. Persistent
   Arduino applications, endpoint program installation, multiple devices,
   streaming observations, on-device agents and microscope commissioning need
   their own resource, timing, failure and qualification contracts.
6. Complete the outstanding primary-source reading and evidence notes. The
   adjacent Bud-Meta-Harness repository, physical hardware, live inference and
   device services remain untouched by this candidate's host simulations.

The system should expose the same operation identity, ownership, observations
and reconciliation semantics whether intelligence is on the device, a GB10-class
hub or another host. Available capabilities and qualified timing guarantees are
specific to each installed provider.
