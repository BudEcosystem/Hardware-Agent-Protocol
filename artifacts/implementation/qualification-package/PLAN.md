# Qualification package and installed source identity

The passing main runtime supplies the Journal/compiler/resource foundation.
The actual qualification service still lives in an isolated project with flat
supervisor imports and several top-level evidence packages. Convert that code
into `hms_qualification`, with a fixed `supervisor` subpackage and the existing
evidence, vault, authority and catalog subpackages. No caller selects imports,
entry points or search paths.

Preserve all finite qualification cases, original operation/attempt identities,
evidence semantics and execution limits. The worker image must include both new
package initializers and every original supervisor dependency. The fixed entry
uses only its protected image root and pinned dependencies. Source identity must
change with packaging; historical receipts retain their old source pins.

First verify the namespace, source closure, import origins and import-time purity.
Then run the full original thirty-case worker, actual reducer/vault publication,
catalog promotion, one simulated application and cold original-key history under
the original 60/180-second and storage bounds. No actual oracle substitution in
that scope. Keep every failed or interrupted attempt without repairing case DBs.

This is a packaging prerequisite to an installed runtime service. It does not
replace the required storage provider, public PAT methods, prompt learning or
physical I/O/driver/hub providers. Public qualification remains gated on enforceable
storage capacity and explicit control-only recovery. The main runtime stays at
its verified 861-test source until the package is ready for integration.
