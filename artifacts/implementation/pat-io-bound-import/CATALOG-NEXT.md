# Versioned catalog integration requirements

The current `hms.pat_catalog.Evaluator` has an exact two-argument `evaluate(artifact, environment)` callback. It receives neither the authority context nor evaluator/run/configuration identities. The finite-I/O importer instead resolves an actual installed execution store and an original committed run. Hiding that invocation in a closure or silently changing the old callback would lose an explicit, reviewable association.

A new recorded-evaluation interface must carry a versioned invocation with deployment, evaluator ID, run ID, artifact digest, source authority, configuration receipt and original import receipt. The caller names the logical run; the installed adapter resolves every authoritative digest and object. The invocation is not an arbitrary successful-result document and must not select a replacement attempt or execute a worker while recording catalog evidence.

The environment contract must distinguish the original source-device configuration from the isolated worker's reconstructed environment. The original endpoint sessions, binding/installation/argument metadata, driver/compiler identity and relevant resource generations define the evaluated application context. The independently inspected worker reconstruction establishes the finite simulation evidence. A worker's temporary endpoint session cannot stand in for the live source-device session.

Historical import/read must remain available after ordinary configuration/session drift. Fresh promotion or execution must compare the current allowed configuration, evaluator policy and implementation, source authority, bindings, sessions and resource generations against the evaluation. An old successful evaluation remains historical when these no longer match; it cannot authorize current actions merely because its artifact hash is unchanged.

The existing catalog evidence verifier runs under a scoped read-only Journal transaction. `IoEvidenceStore.lookup()` and `reinspect()` cannot be called there: they enter transactions, acquire a supervisor lock, inspect the actual supervisor ledger, and, for reinspection, execute full semantics outside their own Journal transaction. A bridge needs an explicitly prepared semantic validation result outside catalog admission, followed by bounded current-byte and authority/configuration checks through ordinary SELECTs on the shared Journal. No filesystem, external ledger, process operation or nested transaction belongs in that verifier.

Cold, missing, stale or corrupt prepared evidence is an availability refusal. It must neither remove a candidate from conflict checks nor classify a familiar scene as novel and ask the agent to generate replacement effects. The preparation result must be tied to exact input/output closure, consumer version, evaluation policy and original import receipt; a bare successful boolean or digest supplied by a caller is insufficient.

Reading and hashing up to the full imported closure under an admission lock has a measurable cost. The existing per-document/count/byte limits establish finite work, not a latency guarantee or protected control capacity. Measure this path and preserve current-byte integrity; do not replace it with trust in mutable cached digest columns. Real-time device loops and emergency control remain separate advertised provider responsibilities.

Keep producer and consumer identities explicit. Adding a host catalog bridge to the conservative producer `hms/` source closure would change the worker identity even if no worker behavior changed. Prefer an explicit host package and consumer version with reviewed transitive dependencies. A new consumer version needs an explicit compatibility/revalidation contract; existing immutable evaluations must not be silently rewritten.

Required next checks include exact historical replay, changed current configuration/session, revoked permissions, consumer/evaluator source drift, cold preparation, modified/missing retained bytes, cross-run substitution, concurrent evidence conflict and the catalog's SQL/reentry guard. Full public CLI/MCP and Harness routing must then exercise qualification, versioned promotion, deterministic reuse and structured novelty without confusing unavailable evidence with a new scenario. None of this integration is claimed by the current worker/import test.
