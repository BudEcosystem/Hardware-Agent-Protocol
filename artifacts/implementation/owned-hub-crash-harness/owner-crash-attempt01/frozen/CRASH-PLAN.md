# Actual provider-owner death controls

This extension uses the already checked dedicated guardian to run twelve fixed owner-death cases against exact copies of the recovery increment's CPU-job provider. Every case has a fresh private ledger and a single original typed integer-series job. No caller executable, hardware, GPU, service, credential or external endpoint is involved.

The owner stops at one private checkpoint: admitted, launching, ownership_registered, spawned, associated, before_release, release_intent, gate_released, writer_settled, before_reap, reaped or terminal_committed. It sends at most 4096 bytes of checkpoint evidence and waits behind a pipe whose only writer belongs to the guardian. The guardian intentionally kills only its registered direct child through its retained pidfd. Kernel adoption and a new child-relation check independently establish authority over any orphan job. A persisted or reported job PID never grants signal authority. Already reaped job PIDs are not reopened or inspected.

Reopening must preserve the exact durable row and original request key. Historical start must not spawn. A still-held writer lease may defer recovery; after all owned/adopted children settle and are individually reaped, an unreleased row must become not_started, a released row without a terminal commit must become unknown, and an existing valid terminal receipt must remain completed. Completed receipts are checked against an independent sum. Missing output is not reconstructed and unknown work is not repeated. This is process-death evidence, not power-loss durability or arbitrary-process containment.

The outer guardian freezes all original harness/provider/helper inputs into a new owner-crash-attempt01, verifies the 244 public baseline files and recovery source pins before/after, and holds the interpreter image for exec. Bounds remain 30 seconds wall and CPU, 512 MiB address space, 1 MiB per file and 64 descriptors for the control; each fixed owner has 5 CPU seconds and 256 MiB address space, while jobs retain their unchanged 2 CPU seconds/128 MiB/4-second wall profile. Cleanup uses ten seconds TERM grace then an eight-second observed guardian settlement bound. Failure of the outer guardian or an unresponsive kernel task remains outside the qualified slice.

Run only after source review: `python3 -I -S -B run_owner_crashes.py`. Do not alter an existing attempt or rerun unchanged adoption/attribute controls. This extension does not qualify aggregate host capacity, public control storage, early leader exit with a deliberately retained writer, a real GB10 provider, or independent physical stopping.
