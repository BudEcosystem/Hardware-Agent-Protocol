# Dedicated ownership harness

This original test harness runs in a fresh sole-thread Linux/glibc/x86-64 process with default SIGCHLD, no SA_NOCLDWAIT and no competing reaper. Its original binding was built and passed nine attribute-only checks, with no children. Primary subreaper manuals and the previous wait/pidfd packet supply the declared API contract. No vendor test or device code is executed.

`guardian.py` enables subreaping only for its dedicated process. Forked descendants do not inherit that attribute; each guardian explicitly enables its own. A kernel `waitid(P_PID, ..., WNOWAIT)` child-relation check precedes pidfd acquisition. The unreaped child and sole-reaper contract preserve identity through registration. Only held pidfds may signal registered kernel children. Stored job PIDs, process groups and ancestry observations alone confer no authority. Registration, reap/publication and final attribute restoration guard INT/TERM interruption windows.

The first control creates fixed two- and three-process trees, each member in a distinct session. The last descendant is held behind a pipe whose only writer is the guardian. Before each intermediate parent dies, a non-child registration must refuse. After its intentional SIGKILL, the orphan must become an actual child before any signal authority exists. All five test children are individually reaped. Final `waitid(P_ALL)` ECHILD and an empty kernel children list establish that this fixed tree has no remaining child; bounded /proc snapshots do not substitute for this predicate.

An outer dedicated guardian owns the control process. On an overdue/interrupted control, it requests orderly cleanup with TERM, waits at most ten seconds, then settles its current/adopted children using live child authority and SIGKILL under an eight-second observed bound. This handles the control process's separate-session descendants while the outer guardian remains alive. An unresponsive kernel task or failure of the outer guardian remains an unresolved failure; no universal containment, real-time bound or top-level process immortality is claimed.

Run the reviewed control once with `python3 -I -S -B run_guardian.py`. Sources/helper bytes are frozen in a new guardian-attempt01; the existing 244 public input hashes and interpreter are checked before/after. The control has 30 seconds wall, 30 CPU, 512 MiB address space, 1 MiB per-file and 64 FD ceilings; its fixed descendants have 5 CPU seconds and 256 MiB address space. Each script/data pipe is bounded. No provider job, GPU, device or physical I/O runs in this first control. Actual provider-owner death is a subsequent source-reviewed harness extension, never inferred from these adoption checks.
