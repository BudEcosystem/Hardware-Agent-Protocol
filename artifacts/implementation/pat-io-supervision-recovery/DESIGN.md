# I/O supervisor failure and owner-loss evidence

The next boundary applies the existing durable supervisor to PWM and I/O-specific
failure cases. All 237 inherited project files, including the five production
supervisor modules, remain unchanged. Two original test files add 20 methods.
This stage does not mount public qualification or implement device providers.

The control selection retains the original 160 tests and adds eleven methods.
It permits only explicitly selected private supervisor SQLite ledgers and forbids
subprocesses. Corrupt rows use separate predeclared fixtures; both the prior row
and the corrupted bytes are retained, and the corrupted database is never repaired.
The diagnostic PID and selector-clock fixture have no process or physical effects.
The original 16 MiB scratch collection bound remains.

Nine separate process selections cover PWM, the original 500-record cutoff,
a reduced 1 ms parent deadline, failure to acquire a pidfd after a real spawn,
and hard owner exit after admission, launch intent, spawn, producer settlement,
and archive commit. Each has its own retained root and original 180 s outer bound.
The normal group keeps its 60 s execution ceiling and all original effect, case,
file, record, storage and transport limits. Collection retains the existing
256 MiB supervisor-root bound, 8192 files and 16 MiB single-file bound.

The crash driver is fixed original test code under isolated Python startup, with
bounded private configuration, no cached bytecode and no network. Its audit hook
allows one exact supervisor worker entry and its own ledger. Its two output
streams are retained up to 65536 bytes each under a 90 s driver deadline. The
outer test has no inherited worker handle and may not signal a stored PID. It
waits at most 70 s for the exact writer lease to become free. That establishes
quiescence, not a known exit code or semantic success. A committed archive keeps
its previous result; earlier owner-loss points remain nonpassing.

The process harness independently locks the owner and exact writer lease before
inventory and retains those locks through copying. If ownership or quiescence
cannot be established, it leaves the raw root and refuses collection. It does
not kill a process reconstructed from a PID. A reparented zombie is not evidence
of a live writer. Parent SQL receipts describe only the test process; driver and
worker SQL are separate fixed child scopes. Cooperative hooks are not an OS sandbox.

Full PWM and completed crash groups are checked by the independent group reader.
A completely delivered failed group must still fail qualification. Exact logical
replay returns its retained attempt without a second launch or fresh planning.
No physical device, acquired controller, live inference, MCU or adjacent Harness
execution is authorized by this stage. Actual aggregate quotas, public service
mounting, agent synthesis, persistent applications and hardware qualification
remain outstanding. Primary-agent review only; helpers are unavailable until reset.
