# Source review and bounded execution plan

Status: **unexecuted**. Root review of the frozen source packet and runner is
required before imports, compilers, native evaluator or host controls run. No
part of this source preparation executed candidate code. Partial control success
must not be reported as completion of the full approved standing host plan.

The new files are a strict v2 codec, native pipe bridge, closed installation
contracts, shared-profile logical accounting, standing store/coordinator,
literal PAT compiler/catalog, original native fixture, nineteen original controls and
one bounded runner. The copied Journal, Registry and ResourceCatalog are the
only public Python modules changed in the candidate. Source copies and exact
diffs identify every overlay separately; public originals remain unchanged.

The explicit local-sqlite-ordering-test profile owns one shared claims table and
resource floors, both finite/standing aliases, original deployment key and
selection provenance. A standing deployment claims acquisition/output atoms and
an endpoint slot/lifecycle atom. Hub/service dependencies appear in the original
topology proof; containment alone does not claim a hub or create a quantitative
reservation. The candidate is installed only in its original test assembly.
There is no public mount, physical transport or commissioned driver.

Host operations are explicit pristine initialize, prepare, one-shot OPEN,
START/RENEW/SUSPEND/RESUME/STOP/RETIRE, collect, read-only reconcile and common
REVOKE, and explicit never-handed-off abandonment. A durable `prepared` record
may be settled only before it was marked `possible`; exact same-boot STATUS
joins verify that its endpoint sequence was not consumed. The original key/body
remain retained as `never_handed_off`. No `possible` original can use this path.
Prepared OPEN abandonment additionally requires no common REVOKE outbox and
matching empty descriptor/counters. Allocated host numbers/fences never regress;
confirmed endpoint floors are derived separately from accepted OPEN history,
allowing explicit unused allocation gaps without accepting endpoint-ahead drift.
One Journal-attached route mutex serializes senders; blocking transport
never holds the Journal authority mutex or an open authority transaction.
Source/driver/qualification snapshots are acquired before transactions and held
through commit. The last veto after possible-send COMMIT only withdraws already
admitted permission; it is not a hard real-time or atomic policy-to-I/O promise.
The endpoint independently applies its installed tick/source/fence/context gates.

Collection commits activations and any loss episode in one transaction. ACK
reservation is a subsequent transaction: a crash in between retains the prefix
and sends no ACK. This deliberate two-commit refinement preserves the required
commit-before-ACK property without pretending the endpoint exchange is atomic
with SQLite. It needs explicit recovery coverage. Ordinary mutation or ACK
ambiguity never authorizes a new original body. Catalog withdrawal blocks fresh
extension; it cannot prove the existing output stopped.

`run_checks.py` has one fixed invocation and creates a new `host-attempt01`.
Existing attempt directories are never overwritten. It freezes all copied/new
project inputs, owner bytes and review documents; hashes the public244 receipt
and every original before and after each command. It performs four fixed owned
commands, stopping on the first failure:

1. Compile the exact twelve-source native qualification image with installed
   GCC13 and explicit warnings-as-errors.
2. Persist/fsync its exact canonical original reservation, then run the original
   native controls. Require exact12-case/638-assertion stdout, exit0, empty stderr,
   one original no-fork child reaped and no remaining handles. Only then publish
   the original receipt/manifest consumed by the PAT producer.
3. Compile the actual native standing pipe using the same endpoint sources.
4. Run the original nineteen host controls against that owned image and original
   qualification bundle.

The selected GCC13, cc1, collect2, assembler, linker and interpreter files are
pinned before/after. `-B` fixes the installed GCC backend prefix and a closed PATH
selects assembler/linker aliases. Native system headers/specs/start objects/
libraries, loader and Python packages remain trusted unpinned dependencies.
This is not a complete toolchain closure claim. An executable's exact held FD is
bounded-read/stat/hash verified before fork and after reap, shared-locked through
launch, and executed through `/proc/self/fd/N`. The fixture does the same for its
native image before connecting its inherited private AF_UNIX peers.

The unmodified sealed Guardian and exact helper bytes provide sole-thread live
subreaper ownership, raw SIGCHLD default/no-NOCLDWAIT checks, kernel-child/pidfd
registration, iterative adoption, settlement and reaping. No durable PID grants
signal authority. The outer guardian owns compiler/control processes; the control
process owns each native fixture. The parent holds only the intended pipe/socket
ends; EOF stops the fixed fixture. No arbitrary programs, physical services,
network operations or devices are exposed.

Per command: observed30s wall bound,30s per-process CPU,512MiB address space,
1MiB file size,64 FDs, core0. The original qualification child lowers CPU to10s.
Fixture children use the unchanged Guardian5s/256MiB profile. An orderly TERM

are per process; the fixed reviewed original qualification has no fork.
`spawnCount` records association and is not a kernel process quota. Descendant
ownership requires the living guardian and is not universal containment.
Every native fixture must return its joined cleanEOF exit0; reaping a crashed
fixture is not a successful case. Both inner results and outer reduction check
those original exit records. SIGINT/TERM are masked during cleanup/publication; pending delivery and terminal
unmask failure force failure receipts. Cleanup actions are independently tried
and errors retained. Neither runner death nor host power loss is qualified.

The nineteen proposed controls are:

- prepare→OPEN→START→activation/feedback→commit→ACK→STOP/episode→RETIRE;
- finite/standing conflicts in both directions, direct Registry aliases and
  lifecycle refusal, including same original key across families;
- OPEN reply lost after durable rx, owner reopen and explicit observation;
- ACK reply lost after durable rx, reopen and read-only exact acceptance join;
- activation collection rollback after rx commit, no speculative ACK;
- held-image expiry after OPEN possible-send commit, no native OPEN handoff;
- endpoint reboot between descriptor pages, no admitted replacement;
- original renewal replay under withdrawn policy, fresh renewal refusal and
  bounded loss cleanup;
- committed suspension episode followed by explicit RESUME then separate START;
- finite ordinary event exhaustion with retained cancellation/terminal/release
  slots, plus refusal of an unknown writer table;
- explicit settlement of a prepared START after reopen, preserving its key/body
  and admitting a separate new START without retrying the old original;
- explicit never-handed-off OPEN settlement and subsequent deployment with
  higher allocated numbers/fences against unchanged confirmed endpoint floors;
- wrong-identity successful OPEN reply injected into the real queued native
  frame with a valid FCS, durable raw conflict and sticky dispute after reopen;
- malformed STATUS state injected on the actual stream with the same durable
  conflict/unknown retention;
- finite admission and dispatch withdrawal at the last business commit check;
- standing owner epoch recovery beyond the32-bit range, sharing Journal's
  safe-integer owner epoch domain;
- prepared automatic ACK settlement followed by a separately admitted ACK key;
- possible common REVOKE with prepared OPEN refusing abandonment and preserving
  claims/uncertainty, even when the native counters show no received OPEN;
- policy-object replacement after finite admission or dispatch recheck, refusing
  the commit while retaining the original accepted operation and zero handoff.

These use real native processes and deterministic private ticks. Fault injection
raises inside the living host or deliberately discards a processed reply; it
**does not kill the host owner**. Remaining required qualification includes actual
owner death after committed prepared OPEN and prepared mutation/ACK reservation,
and at possible OPEN, START, collection-before-ACK and ACK handoff;
retained endpoint continuity while the ledger owner dies; lost-RETIRE recovery;
wrong-response retirement/dispute controls; refused-sequence reuse; automatic ACK
revision refusal; episode/mutation/key/full logical capacity edges; metadata
headroom and storage failure combinations. These remain failed/unimplemented
completion gates until separately implemented and executed with actual ownership
and cleanup evidence. The initial nineteen-case run, if approved, is a partial
validation step and must be labelled that way.
