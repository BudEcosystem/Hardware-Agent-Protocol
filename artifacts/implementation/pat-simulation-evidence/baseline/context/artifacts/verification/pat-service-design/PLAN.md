# Next milestone: installed simulation qualification services

Design only. No production changes, tests, model, hardware or acquired program execution were performed. The 22 exact input snapshots in `inputs.json` record the implementation and planning context. Their acquisition is not a claim of complete reading. Runtime regression repair and its pass/fail receipts remain a separate lane.

Implement a trusted, executable **simulation qualification service and reproducible provider configuration before public PAT mutation tools**. The current `Evaluator` interface accepts installed code, but the catalog tests deliberately return synthetic check results. Publishing those fixtures as a qualification service would not validate a program. Disabled-by-default injected services are a useful embedding seam, but mounting that seam alone is not the next meaningful end-to-end result.

## Small, explicit semantic target

Start with one allowlisted policy, proposed ID `hms.pat.eval.sqlite-fan-sequence/0.1`. It supports one fan role, one to sixteen `set_level` steps, explicit percent units, at most two varying bounded integer parameters, existing static equality/range applicability, and only the original `sqlite-simulation` driver. Unsupported actions, extra roles, frames, data references, dynamic observations, persistent controllers or unrepresentable case sets refuse qualification. Extend through separately versioned policies later.

The existing PAT outcome contract requires listed steps to complete with simulation capability evidence. It cannot express “the enclosure stayed cool,” physical airflow, image quality or a general application objective. This policy's additional oracle is narrowly defined: for each positive case, the isolated simulated fan reaches the last declared set-level value, the committed simulated effect count equals the distinct executed steps, each operation has the expected receipt, and no resource claim remains. The policy ID/digest identifies that oracle; a receipt must not rename it generic task success or physical verification.

Whole-domain compiler checks and finite behavior trials are different evidence. Reuse `parse_pat`, `matches_static` and `compile_pat` to prove supported parameter-domain inclusion, units/frames, finite instruction structure and timing/effect limits. Run a deterministic finite matrix of applicable nominal and boundary values, rejected out-of-domain/type/applicability values, exact replay/conflicting-key cases, cancellation and restart/unknown-result recovery cases. Record every concrete input and expectation. Boundary sampling is not an exhaustive proof of behavioral correctness over all integer combinations. An empty applicable domain, unsupported oracle or oversized required matrix fails closed rather than silently reducing coverage.

## Minimal service/configuration changes

1. Add a closed `hms.pat.simulation-services/0.1` configuration and original service module. Configuration chooses allowlisted profile/policy IDs, explicit semantic registrations and an artifact-digest-to-role-instance qualification map. It contains no Python import path, callback, command, URL, caller result or `passed` flag. Compute implementation/policy/driver code identities from the installed reviewed source closure; do not take arbitrary implementation hashes as attestation. Pin the canonical configuration digest in a small versioned authority configuration record. Reopen reconstructs the same installed services; missing or changed configuration/code refuses new qualification/reuse until explicitly reconfigured and re-evaluated. It must not silently rewrite the old configuration.
2. Construct `RegistryPatBindings`, a current environment provider, `Evaluator`, `PatCatalog` and `PatExecutionStore` from trusted setup after registry/adapter/procedure initialization and before workers. Environment construction must reuse a pure compiler environment-extraction helper shared with `compile_pat`; it must not fabricate operation keys or use sample parameters as a substitute for dependency identity. Keep direct public mounting disabled in this milestone. Existing catalog authority and promotion revision checks remain authoritative; do not auto-publish, auto-promote or run live business actions during startup.
3. Implement the evaluator callback against an isolated worker running only original local-simulation code. Pass a detached artifact and exact tested installation/binding/metadata snapshot through bounded data, create separate authority and plant databases, use deterministic virtual clocks, and provide no live Runtime object, authority path, endpoint FD, network/model provider or physical driver. Validate that the reconstructed static environment equals the requested environment. Do not import test fixtures as the service implementation.
4. Retain an immutable attempt input before starting the worker, then concrete case results, receipts, effects/claims and failure/timeout diagnostics under content-addressed evidence references. Check referenced bytes before returning evaluator results. Preserve raw nondeterministic record IDs rather than normalizing away conflicting evidence. A wrapper `qualify(context, artifact_digest, evaluator_id, run_id)` admits at most one active qualification with a bounded queue or explicit busy refusal and delegates committed run-ID replay to `PatCatalog.evaluate`.

Proposed initial policy ceilings are 32 cases, 512 distinct child operations, 2,048 virtual scheduler ticks, 16 MiB retained output per attempt and a 60-second worker deadline with bounded output collection. These are engineering limits to implement and measure, not demonstrated performance. Configuration may lower them; increasing them changes the policy identity. Exhaustion is inconclusive/refused, never passed. No fixture result may override it. Retention quota exhaustion must refuse before starting another attempt and preserve prior evidence. Worker/process isolation is not a qualified real-time or malicious-code sandbox.

The catalog currently registers no durable in-flight evaluation before invoking its callback. An attempt archive can preserve a crash without pretending a catalog receipt committed. On reopen, retain unfinished attempt records as interrupted/inconclusive; retrying an uncommitted evaluation may rerun isolated trials. Do not claim evaluation exactly-once execution. Unknown isolated outcomes must be reconciled from retained simulation receipts before declaring zero unresolved effects; deleting their databases is not evidence of resolution. A public asynchronous evaluation/job protocol can be designed later if needed for transport deadlines.

## One artifact and multiple bindings

An artifact may be reused across deployments when its typed semantics remain unchanged, but each deployment needs its own concrete environment and qualification receipt. Within one deployment the current catalog stores **one latest evaluation/environment per artifact**. Qualifying that artifact for west replaces its latest east evaluation, suspends active reuse and requires explicit promotion; already admitted east instances keep their pins. This milestone must preserve that behavior, not imply simultaneous qualification of one artifact for both assignments.

Do not clone artifacts with misleading names merely to conceal this limit. Simultaneous environment alternatives require a later catalog redesign keyed by artifact plus qualified environment/assignment, with revised promotion and ambiguity rules. A role map must close exactly over declared roles. Changed calibration/driver/installation/metadata invalidates qualification. A focus artifact with an explicit device-specific frame may require a different artifact; no implicit frame conversion is allowed.

## Acceptance checks to implement

- Actual isolated execution produces independently inspectable receipts and state/effect assertions; changing the oracle, a result, a dependency or an evidence file prevents promotion.
- Whole-domain rejection cannot be hidden by passing nominal values; all required case categories and all attempted cases affect the result.
- Malformed/unsupported configurations and programs, incomplete matrices, worker failure, deadline/output/quota exhaustion and unresolved outcomes fail closed with retained evidence.
- Live authority business tables, plant values/effect counts and endpoint traffic remain unchanged by qualification; only authorized catalog/configuration/evidence bookkeeping changes.
- Exact committed evaluation replay reuses its receipt; competing/changed results retain conflicts; interrupted attempts survive restart without a fabricated pass. Services reconstruct after reopen from the pinned config.
- East/west qualification demonstrates the single-environment limitation explicitly; separate deployments retain separate receipts for the same artifact, and metadata or frame changes are not silently generalized.

These are planned checks, not executed results.

## Subsequent public mounting and domain work

After that service is usable, expose `pat_run`, `pat_status`, `pat_cancel` and `pat_resume`, followed by separately authorized catalog/evaluation management. Runtime must own the configured stores. Extend `scripts/build_api_schema.py` and regenerate `schemas/local-api.schema.json`; add strict pre-canonicalization input and request/result correlation in `hms/api_contracts.py`. Reuse the checked `Client` and existing UID-authenticated IPC without transport retries. Add CLI parsing and `hms/mcp.py` descriptions/mutation annotations; the stdio transport need not invent another lifecycle. Preserve original requests after missing replies, validate nested procedure status, enforce the 65,536-byte carrier bound, and keep MCP cancellation distinct from PAT cancellation. Test full daemon/CLI/MCP lost-reply and restart paths before claiming public support. Adjacent Harness checkouts remain untouched; a future separate integration lane can consume the stable API.

Then add an episode/trace export and declarative candidate-proposal contract so observed successes, failures, refusals and unresolved effects can inform candidate generation and novelty escalation. Deterministic reuse alone is not experiential learning, and no model execution is needed to implement this contract.

I/O and hub work remains a separate required implementation track. Current adapter schemas hard-code two simulation drivers and fan/focus/inspection maps; resource claims use flat exclusive IDs. Missing schemas include electrical pin modes/ranges, pin/timer/bus/DMA alias closure, driver generation/dependency and drain/replace recovery, compute capacity/placement/quotas, stream/data-reference retention and gaps, and hub/service shutdown/restart dependencies. The smallest later domain slice is a versioned resource dependency/alias schema with original simulations proving raw GPIO and peripheral aliases cannot bypass shared claims, plus a simulated hub-service dependency generation change. Neither this design nor public PAT tools installs those providers or completes persistent Arduino applications.
