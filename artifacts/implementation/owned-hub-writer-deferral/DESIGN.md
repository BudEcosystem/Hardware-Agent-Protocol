# Deterministic inherited-writer deferral

This source-only increment copies the sealed recovery provider and the sealed guardian harness into a new directory. `guardian.py` and its native binding remain byte-identical. Original provider contracts, ledger, package marker and signal-query helper also remain unchanged. Only provider/worker fixture wiring and the dedicated control/outer runner are extended. `parent-pins.json`, `baseline/`, `source-diff.patch` and `change-pins.json` join the exact originals to this candidate. No candidate has run.

The private installed `writer_barrier` mode receives exactly two FIFO descriptors: a held-writer pipe reader and a ready-notice pipe writer. It is not a caller request field. Their role/access/device/inode identity is captured in the installed artifact manifest and rechecked before fresh launch/release. The normal request retains its closed typed arithmetic input, original key and limits. There is no caller executable, path, module, command or arbitrary descriptor list.

The original admission gate remains unchanged: only committed release intent followed by G permits the fixed worker to fork its one computation child. The worker leader then closes its own fixture descriptors and exits normally with code zero. The child computes the original bounded sum, writes its normal result while the provider owner still holds the stdout reader, and emits a separate bounded ready notice. That notice contains the request digest, launch nonce, artifact digest, exact lease device/inode, original leader identity, child PID/start ticks/session/group and computed result. It then blocks on a second pipe. This barrier controls retained writer lifetime after computation; R does not initiate extra computation. No sleep establishes the hold.

Only the live guardian has the second pipe's writer. The fixed provider owner closes its inherited writer copy before launching any worker; the provider passes only the reader and ready-notice writer through exec. On guardian loss, EOF unblocks the fixed child. That is an additional finite-fixture constraint, not a universal guardian-death guarantee.

The provider owner services the original release once, then uses only its retained unreaped child waitid observation to prove the leader's normal exit. It never uses Popen.poll/wait to consume that leader. It publishes a checkpoint and blocks behind a separate guardian-owned pipe. While that owner remains alive, the computation child becomes the guardian's adopted child because the intermediate worker leader has exited and the provider owner is not a subreaper.

The guardian obtains the writer from its kernel child enumeration and registers a pidfd before comparing the ready notice. A reported PID does not grant authority. It positively checks the associated ready notice, artifact/pipe identity and a separately opened matching lease inode whose flock is held. It then kills and reaps only its owned provider owner, adopts and reaps the already normally exited worker leader, and again proves that the same writer is alive and the independently opened matching lease is held. Reconciliation starts only after owner death releases the ledger lock.

Reopened original-key replay must create no process. Reconciliation while the writer is held must return the unchanged released row with no receipt, and both committed slot bytes must remain unchanged. A second lease probe must still fail to acquire the matching inode. A fresh key must be refused while that unresolved row occupies admission.

Three fixed controls then settle the held writer: R releases it with exit zero; EOF produces the fixture's exit 79; or the guardian sends SIGKILL through its held pidfd. Each case individually reaps its provider owner, normal-exit worker leader and writer, then requires kernel ECHILD/empty children. Only afterward must an independently opened matching lease be free. Reconciliation produces recovered `unknown`, with no invented result or exit code, despite locally observed calculation bytes. The terminal row and original-key replay must remain stable without relaunch.

These three cases extend the previous owner-death packet, whose twelve initial lease observations were all free. That historical result remains unchanged. This new packet does not claim a public mount, hardware or driver operation, GPU/GB10 readiness, aggregate capacity, physical storage durability or universal process containment.
