# Source review

The parent project and runner are pinned by [source-pins.json](source-pins.json) and the sealed index. The candidate source changes are original, isolated and unexecuted. Root's object inspection is retained separately under `artifacts/verification/standing-size-analysis/attempt01`; it inspected existing object bytes and did not execute an AVR image.

`finite_describe` writes the same five fields: maximum run 1000, resource mask 3, SIMULATION evidence bit, cancellation supported and zero result length. The descriptor is a callback-local output with no concurrent observer. Assigning each field preserves every value and removes the source aggregate that the retained AVR object copied from an eight-byte SRAM-backed constant. Only a new object/map can establish the resulting storage and flash effects.

`feedback` now uses `int32_t` for demand improvement. Both operands are accepted channel-0 values in [-100000,200000]. The baseline is copied from the accepted demand only after a confirmed ordinary output dispatch; feedback is evaluated only while an ordinary activation remains pending. Failure/loss cancels or makes that pending record unknown before any subsequent ordinary feedback calculation. Each later transition replaces the baseline. Therefore the difference lies in [-300000,300000] and cannot overflow signed 32-bit arithmetic. Callback mutation of controller/arena storage is already forbidden. This proof does not extend to arbitrary corrupted backing storage or future expanded value ranges. Timestamps and conservation accounting keep their previous widths and boundaries.

The new `feedback_signed_range` control uses two complete OPEN/acquisition/START/dispatch/feedback paths. In the positive case, baseline 200000 falls to -100000 and must satisfy an improvement requirement of exactly 300000. A 100 ms minimum ON dwell prevents a second OFF activation from obscuring the result at the evaluation tick. The reverse case starts at -99999 and rises to 200000, so an improvement requirement of 1 must remain unsatisfied despite valid actuator feedback. It fails at tick 64, performs loss output at 65 and accepts a subsequent zero-valued aggregate witness at 66. Both paths inspect dispatch at 14, feedback acquisition at 25, retained records, effect counts and ownership. Existing twelve scenarios remain unchanged.

Exactly four timestamp comparisons change, at parent lines 290, 563, 568 and 693: renewal lease <= retained lease; feedback acquisition > dispatch; demand acquisition > dispatch; loss observation <= loss handoff. Each compares two canonical eight-byte big-endian unsigned values. The sign of `memcmp(a,b,8)` has the same order as numerical decoding because the first unequal base-256 digit outweighs every subsequent digit combined. The original relational operators, short-circuit order, preceding ABSENT checks and callback order remain unchanged. This equivalence covers all bit patterns; it does not depend on host byte order or any particular nonzero return magnitude. The two acquired-local aliases, native timestamp fields and all time arithmetic remain untouched. [ENCODED-TIME-REVIEW.md](ENCODED-TIME-REVIEW.md) records the exact operands.

No `noinline` attributes or compiler flags change. Size effects will be reported only for the combined candidate. No code-size benefit, native pass or target-fit result is inferred from this source review.
