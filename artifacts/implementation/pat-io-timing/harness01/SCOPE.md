# Pure65 execution scope

Run the closed 65-method selection: 20 existing compiler methods, 14 fixed-unit
methods and 31 new I/O static-contract methods. The inherited Runtime execution
method is excluded. No test may connect to SQLite, create a child process or use
a network socket. No provider tick, qualification worker, model, endpoint binary,
physical port or user authority directory is used.

The launcher verifies the frozen 163-entry candidate, acquires a new 157-file
project copy, pins seven selected installed distributions plus Python/SQLite
extension files, and starts one owned `-I -S -B` child. Actual project/dependency
origins and bytecode refusals are recorded. Setup may read source/schema identity
files; the new purity method vetoes files/clocks/providers after trusted setup.

The default child deadline is 180 seconds, with owned terminate/kill cleanup.
Input/log/JSON/scratch collection bounds are preserved from the original pure34
harness. They are cooperative collection limits, not a disk quota or OS sandbox.
The adopted resolver03 scratch checks require the same trusted `/tmp` ancestor
and private 0700 directory before/after collection. Original raw scratch is never
deleted by this runner, including after successful copying. Failed attempts and
their sources remain retained.

Source review and execution release here are decisions of the primary agent
within the user's authorized original-host-test scope. There is no independent
review while helper agents remain unavailable. This runner does not promote a PAT
or alter the live runtime. Compiler and I/O source identities are retained before
and after; the compiler's optional-dependency identity gap remains separate.
