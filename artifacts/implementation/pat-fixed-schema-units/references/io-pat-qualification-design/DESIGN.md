# Finite GPIO/PWM PAT simulation qualification: next increment

This is an original design, not an implemented evaluator or a qualification receipt. The 22 selected inputs are copied and hashed in `inputs.json`; the reading ranges are recorded there. No project module was imported, and no test, worker, Runtime, device, model or lifecycle command was executed for this design. The separate full747 regression was still running when these inputs were captured. Its result must be reported by its own receipt.

The minimum useful extension is a separate, versioned **finite I/O sequence qualification policy**, using the existing PAT ordered-sequence IR and the original shared-board simulator. It must leave the fan policy and its historical receipts intact. GPIO/PWM execution support is already present in the inspected source; that does not establish PAT compiler compatibility, qualification, public PAT service mounting or physical objective verification.

## 1. Small eligible program and explicit semantics

Propose policy `hms.pat.eval.sqlite-finite-io-sequence/0.1`, with distinct I/O input/result/matrix/evidence profiles. One artifact has one role, one installed action, and 1..16 ordered steps of that action. The trusted handler map must resolve that action to exactly one of `gpio_pulse` or `pwm_burst`; do not identify semantics from the action's spelling. Require capability `sim:finite-gpio-pwm`, driver `sqlite-finite-io/1`, simulation placement, existing static selection predicates and installed primitive guards only. The same policy may handle either primitive; a single artifact initially cannot mix them. Other roles, branches, data references, dynamic applicability, sustained predicates, lifecycle actions and persistent controllers refuse explicitly.

Allow integer literals and parameter references, at most two varying integer parameters, plus bounded singleton parameters. Keep exact bool/int/float distinctions before canonicalization. Compute the exact intersection of declared domains with supported static applicability; refuse empty, unsupported or oversized matrices. Prove the **whole declared domain** against both type and binding schemas before that intersection. Narrow applicability cannot repair an invalid advertised domain.

Trusted semantic units must be explicit: GPIO level is dimensionless `1`; duration is `ms`; frequency is `Hz`; duty is `permille`; resolution is a bit count with an explicitly chosen fixed label, e.g. `bit`. Frames are null. These labels are policy choices to freeze in trusted metadata, not inferred from names. Preserve the timer's exact frequency envelope and 8-bit resolution. No percentages-to-permille conversion or voltage/physical interpretation is implied.

There is a concrete compiler blocker: `pat_compiler._binding` currently refuses non-dimensionless units without a string companion argument, while the finite I/O schemas have no companion fields. Do not declare milliseconds/hertz dimensionless to pass. The smallest honest change is a separately reviewed closed metadata revision for **fixed-schema units**, explicitly distinguished from the existing companion-argument form. It must be supplied only by trusted installed semantic registration, pinned in `argumentMetadataDigest`, and included in compiler identity. Legacy companion checks must remain unchanged. No caller-supplied unit metadata or arbitrary transformation function is needed. An alternative typed wrapper action would change the provider/API and is larger than this proposal.

Timing is also a domain constraint. `argument_schema` allows duration 1..5000, but generated actions have `maxRunMs=5000`, and `SyntheticIoBoard.begin` rejects `dueMonoMs >= budgetOriginMonoMs + maxRunMs`. Consequently a declared duration including 5000 cannot be advertised as a successful nominal program under current action bounds. Require every declared duration to fit a strict per-step run budget, and prove that the deterministic virtual-time schedule can start and finish every nominal/boundary case strictly before start/completion/lease/run upper bounds. This is a qualification/capability constraint: the current runtime conservatively refuses the excluded start before activation, not a false-completion defect. Retain exact-limit negative cases; do not widen limits or claim a host real-time guarantee. Whole-domain timing validation is not exhaustive behavioral testing.

## 2. Trusted reconstruction and binding selection

Use a normalized full `hms.synthetic-io-installation/1` document and a fresh private `IoRuntime` per trial, with one shared board across all routes. Never open a user's authority directory or copy its effect state. Capture type, binding, full installation, topology, route inventory, generation snapshot and retained resource proof from trusted setup; reconstruct and compare them exactly before trial execution. Fresh state means zero activations/completions/cancellations, no receipts/owners/fences/Journal operations, and the complete expected resource inventory at canonical idle. Random authority/session/operation IDs remain actual evidence, not normalized identities.

The existing `RegistryPatBindings` is **not I/O-compatible**: it expects legacy route installations and calls `installation['instances'].values()`. `IoAdapterCatalog.route_documents` uses an instance list plus a full-installation digest. Add a narrow trusted I/O binding provider or an explicit closed profile branch, not a generic plugin loader. Join and validate the retained route row, full installation, current Registry binding, exact type/actions, driver source digest, explicit semantic registration and ResourceCatalog proof. Missing registration/session for an otherwise authorized compatible candidate is indeterminate; complete enumeration cannot silently omit it. Retain existing 16-per-artifact/128-total assignment bounds and overflow refusal.

Set the compiler descriptor's installation identity to the full normalized I/O installation, which includes every route and topology alias, not just a caller-selected route projection. Validate each route's own retained digest separately. Bind the qualification to the exact resulting evaluation environment and config/policy identities. The current environment includes binding/metadata/driver/installation digests; the binding includes generation and control generation derived from resource proofs. Preserve exact environment matching, not a looser “same board model” comparison.

Fresh routing considers authorized static candidates before transient resource contention or presence age. Busy resources must not select a different alias, PAT or route. A generic artifact may compile for two bindings, but a receipt qualifies only its exact evaluated environment. The catalog currently retains one latest evaluation association per artifact entry: testing the same artifact on two aliases does not make both simultaneously qualified. Additional per-environment receipt indexing is a separate change; this increment must state that limitation.

Current and historical bindings have different uses. ResourceCatalog's current proof check gates fresh execution. IoAdapterCatalog retains installed historical definitions for stop/reconciliation and deliberately makes changed current generations unsupported by the immutable provider. Exact retries retain original operation/procedure keys and bindings; they cannot rebind to a new session or generation. Historical receipt retrieval is not new qualification or permission to start. The separate unexecuted lifecycle stage is outside this design.

## 3. An independently checked outcome oracle

Do not adapt fan success by renaming `finalLevel`: fan completion increments `effectCount`, while finite I/O increments **activation** when the output starts, including starts later canceled. The reducer should derive expected active/idle state and ownership from the frozen primitive policy plus parsed topology and invocation arguments, and compare raw retained rows. It must not accept the worker's `passed` flag, the adapter's projection, or a receipt digest alone as an outcome oracle. Shared canonical parsing and compiler validation are reasonable; the outcome comparison should not just call `SyntheticIoBoard._validate_state` and restate its answer.

| Observed boundary | Independently required facts |
| --- | --- |
| Accepted cancellation before handoff | No provider receipt, activation, board owner or board fence change; exact Journal cancellation proof and released claims. Previously reserved Journal resource floors are not rolled back. |
| Guarded start excluded | Same-ID sequence-1 no-start receipt; activation=false, cycle=false, idle=true; no clocks/owner/fence/effect increment. |
| Pending | Sequence 1; activation=true, cycle=false, idle=false; exact active pin/timer/channel state, matching Journal claims, board owners and fences. |
| Completed cycle | Sequence 2 after the same pending identity; activation=true, cycle=true, idle=true; due time reached within allowed budget; one completion increment and no extra activation. |
| Canceled/failed after start | Sequence 2; activation=true, cycle=false, idle=true; exact bounded reason; one cancellation increment, no completion increment. Never report zero effects. |
| Missing/contradictory state | Unknown/unresolved, held claims where required; no fabricated idle, successful qualification or automatic new-key retry. |

Record the complete board `io_resources`, `io_owners`, `io_fences`, `io_effects`, current receipts and receipt versions; authority dispatch links, retained receipt snapshots, operations, claims, replay rows, resource floors and complete bounded event streams; exact procedure requests/status; and exact request/response outcomes for replay/conflict/refusal. Compare identities and digests across all these records. Emit raw rows for facts that the fan evidence format leaves as pinned-producer assertions. Missing raw facts remain limitations, never reconstructed proof.

At each checkpoint require `activations = completed + canceled + pending` per instance, no unrelated resource/counter changes except explicitly declared auxiliary actors, and no orphan ownership. At final success every admitted actor must be settled and quiescent, with zero unresolved effects. Historical terminal receipt idle is not a current idle assertion: a later valid owner may drive the same atom while the earlier result remains readable. Validate `hms.synthetic-io-result/1` separately, preserving activation versus cycle and unverified simulation evidence. A completed provider receipt may precede authority settlement; the oracle must not require cycle=true iff Journal state=completed.

## 4. Deterministic trials and resource isolation

Retain the fan planner's finite nominal/boundary/negative technique, with type tags, case deduplication, explicit constant-domain coverage and no truncation. Recalculate cases and auxiliary operations before launch; fixed fault/resource trials consume the same global limits as ordinary steps. A 32-case/512-child ceiling may be reused as a conservative initial bound, but a matrix that does not fit must refuse, not drop cases. Boundary sampling is not exhaustive domain qualification.

The first mandatory execution set is both primitives, varied supported parameters, and a fixture with shared GPIO/PWM pin, a cross-route alias of that pin, and an independent pad. Artifact trials remain one-role; fixed auxiliary contenders belong to the policy's declared test harness and operation budget. Test (a) GPIO and PWM mutual exclusion on the same pin, (b) cross-route GPIO exclusion with one shared fence history, (c) independent-pad progress, and (d) alias replay without a second activation. Derive atom sets from topology; do not compare alias strings as if they were independent resources.

Mandatory faults: accepted cancellation; running cancellation; reopen while accepted; reopen while pending (exact `board_owner_reopened`, one retained activation); board terminal commit followed by lost authority evidence; lost pending acknowledgment followed by exact reconciliation stop; clock/start/completion/run boundary refusal; and changed grants/binding/session at the relevant boundary. Parent interruption never automatically runs later steps. Exact repeat after settlement must retain IDs, fences and counters; changed same-key payload must conflict. Actual SIGKILL trials belong to a later explicitly supervised process suite, not to a modeled exception labeled as a crash.

Missing receipts, rehashed contradictory ownership, wrong attempts or corrupted current state should be adversarial worker/reducer tests with an **inconclusive retained attempt** when effects remain unresolved. They cannot be counted as successful qualification cases merely because refusal was expected: the current catalog/evidence contract requires a complete passed group with zero unresolved effects. Preserve those failed/unknown attempts separately.

## 5. Evidence, identities, service prerequisites

Use new closed I/O worker/trust/result/case/group profiles and check IDs, e.g. `io:positive`, `io:boundary`, `io:negative`, `io:fault`. A group must cover the exact deterministic matrix and every named resource/fault trial, with no omitted/extra/duplicate cases, cycles or mismatched outcomes. Keep bounded canonical documents (at most 65536 bytes each), full-closure byte/document bounds including derived records, and aggregate store admission. Extra raw ownership/floor/replay evidence may need smaller pages; it is not a reason to raise bounds silently.

Retain source/config/artifact/driver/compiler/evaluator/policy/environment/attempt/run associations. Policy identity includes case-generation semantics, fault definitions, time schedule, limits, required checks and oracle revision. Implementation identity covers worker, reducer, memo, resolver, installation/topology helpers, validation schemas/resources and typed API contract. Compiler/package manifests and selected Python/SQLite binary pins have their documented scope; do not call them full OS/runtime attestation. A later source closure invalidates current qualification; historical retained bytes remain auditable.

The existing reducer and memo are fan-specific imports and profile grammars. Reuse their reviewed mechanisms only through an explicit versioned I/O implementation or a separately reviewed fixed profile branch. No runtime-selected arbitrary reducer callback. Full reduction occurs at import/audit or explicit warming; ongoing verification rereads and hashes the complete authority-DB closure, validates the current catalog receipt association, and reuses only exact typed input/code identities. Catalog eligibility remains SELECT-only with bounded `typeof`/`length` reads. Corruption, cache-cold, unavailable verification and missing evidence abort selection; they cannot manufacture uniqueness or invoke a model. Memo capacity is 8 groups versus 128 catalog entries, so service activation/prewarming needs a capacity policy outside the authority lock and an atomic final recheck.

Do not mount a public service as part of these library changes. The durable supervisor slice still has logical admission and `totalDiskQuotaEnforced=false`, not a hard aggregate storage domain. A trusted service must fix one global root, authenticate the original worker/config, enforce actual storage scope, retain process ownership across crashes, and reuse the exact committed random-ID archive before catalog commit. The evaluator callback lacks runId; a controlled admitted association must bind it, and direct/unadmitted callbacks refuse. Nonpassing/unknown worker returns stay exact retained results, never invented zero-unresolved evaluations. See the copied storage assessment for the still-open enforcement contract.

## 6. Smallest implementation split and acceptance gates

1. **Pure compatibility:** explicit fixed-unit metadata revision and narrow I/O binding provider; strict whole-domain and timing planner. Prove fan behavior unchanged. Refuse bool/float aliases, unknown fields, wrong units, enum holes, empty applicability, >2 varying axes, impossible duration and incomplete inventory before admission.
2. **Original isolated worker + independent reducer:** fresh IoRuntime reconstruction; both primitives and all declared resource/fault trials; raw event/ownership/replay evidence and complete limits. Rehashed mutations of activation/cycle/idle, receipt sequence, fence, attempted binding, event timing or unrelated pad state must refuse even after all outer digests are recomputed.
3. **Versioned DB evidence and catalog connection:** exact import/replay/corruption checks, code/environment change invalidation, bounded cold-cache refusal, and catalog same-run result conflicts. Test two eligible aliases remain ambiguous; resource busy or broken verification never selects another. Test owner/read revocation and exact archived retries after catalog suspension without rerunning the worker.
4. **Trusted service later:** actual storage enforcement, process/attempt lifecycle and atomic catalog association, with crash evidence and retention admission. Only then consider public qualification/run mounting. Persistent event-driven applications, local feedback controllers, physical outcomes, natural-language synthesis and learned candidate promotion remain required broader work, not completed by finite I/O trials.

Every gate above is **planned, not executed in this design**. Existing provider/API/transport test source supplies concrete seams and expected distinctions; its successful execution, where established, is evidence only for its own frozen receipt, not for this proposed qualifier.
