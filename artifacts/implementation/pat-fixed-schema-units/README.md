This source-only stage adds one explicitly tagged fixed-schema unit alternative to the pure PAT compiler. It has **not been imported, compiled as a PAT, or tested**. No live source changed, and no I/O provider, worker, public qualification service, or lifecycle behavior is added.

[Design](DESIGN.md) defines the exact five-field `hms.pat.argument.fixed-schema-unit/0.1` grammar. Both schemas must be numeric; unit is explicit; frame and companions are null. The legacy four-field block is byte-identical. No unit inference, conversion, callback, or wire-argument synthesis occurs.

[Baseline inputs](baseline-inputs.json) pins all 151 source files from immutable full748 attempt `20261107T014321.791506Z-b4b2085264e7`, plus all 26 sealed I/O PAT design files, including its 22 selected input copies. `baseline/` is unchanged; `staged/` differs only in `hms/pat_compiler.py` and the new `tests/test_pat_fixed_schema_units.py`. [Patch](compiler.patch) and [source review](source-review.json) retain the exact delta and a stdlib AST comparison. These structural checks are not passed behavioral tests.

The proposed focused plan is the 21 existing compiler methods plus 14 new pure semantic methods (35 total). One inherited compiler method opens an original Runtime simulation across two local aliases; it is explicitly listed in the source review. A strictly pure first run would select the other 20 plus the new 14 (34 total) and defer that method. All execution remains held pending the parent's review/release. The new tests themselves use original GPIO-shaped/PWM-shaped contract fixtures with explicit fixture identities, not actual I/O installation support or driver attestation.

Legacy invocation-byte equivalence means compiling the same frozen descriptors, parameters, time origin, keys and context preserves the request. It does not mean that changing compiler code leaves deployment, driver, evaluation or environment identity unchanged. Compiler identity already includes this source; metadata digest includes the tag and exact unit. Existing evaluations must fail current-identity checks after an implementation change. The complete current synthetic-provider source digest also changes when compiler bytes change.

The baseline predates the separately owned IDNA dependency-identity correction. That change is intentionally not copied from mutable live sources. Future integration must rebase this small validator branch and retain fresh evidence for the resulting exact closure. The stage does not establish current full-suite coverage, whole-domain execution timing, physical completion, or I/O PAT qualification.
