# Independent fixed lifecycle outcome composition

This pure retained-data stage completes the semantic checks for the twenty
GPIO/PWM captures from the fixed lifecycle stage. It changes no runtime,
provider, compiler, matrix, recorder or existing history fold. The exact fixed
case/artifact, call schedule, original lowering and trusted grant plan are first
checked by the existing partial reader. Configuration decisions, board effects,
operation/procedure events, observations and static timing are then independently
composed, with expected fault responses kept distinct from PAT completion.

The trusted fault list is a separate closed input. Exactly one begin-after-commit
loss is allowed for pending-reply loss, and one authority-record-before-commit
loss for completion-reply loss or post-completion permission withdrawal. Every
new unknown event must occur at that declared cut or the specific pending-owner
reopen. Empty fault plans cannot authorize unexplained unknown events. Completion
loss must preserve the exact completed board receipt and authority retention,
unchanged claims, and an unknown authority outcome until reconciliation. Pending
loss uses the existing independently derived reconciliation-stop context. A new
owner may stop a pending receipt but cannot rewrite completed history or rebind
an old request. Accepted reopen has no effect or dispatch evidence.

Checks cover all paired checkpoints, quiet before/final snapshots, exact public
refusals, current grant revisions and dependencies, every effect/receipt/fence,
held claims through uncertainty, original parent/child requests, event histories,
sample timing/value, returned statuses and final settlement. A completed prefix
with a canceled two-step parent fails the completion objective. Only the declared
single-step after-completion withdrawal case satisfies it. Every scenario must
end with its exact expected effects, parent/child state and zero unresolved work.

The source closure retains 5,088 unchanged inherited files and adds 2,665 exact
lifecycle fixture files plus two new modules. It explicitly excludes 3,013 old
active/authority/recovery fixture files from this new copied closure, leaving
their original sealed stages intact. The 8,192-file ceiling is unchanged. Tests
load the new acquired bytes, coherently rehash adversarial alterations and enforce
I/O/clock purity. No SQL, runtime, physical/MCU, inference or live service runs.
The original bounded harness remains in force. Primary-agent review is used;
the existing independent helpers still report an account usage limit.

This is complete fixed historical-case validation, not current-candidate group
qualification, implementation/configuration attestation, aggregate storage/time
admission, automatic PAT promotion, or actual device/driver/hub management.
