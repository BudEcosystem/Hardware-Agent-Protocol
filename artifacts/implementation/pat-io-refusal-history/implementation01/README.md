# Independent pre-effect permission-refusal composition

This isolated candidate joins the two retained permission-denial cases with the
full configuration, PAT, board, operation, parent and observation checks. The
new composition derives causes from trusted grant history and pre-call state.
Captured reason strings cannot authorize a refusal on their own.

Parent submission must have a live replay namespace, usable start deadline and
no existing replay reservation. A permission refusal preserves every execution
table and creates no parent or child. Before child dispatch, the checker verifies
the eligible time window, runnable parent/prefix, original resource claims,
unissued attempt and current session/presence. An eligible denied child must
actually reject; an event-valid stalled accepted history is insufficient. Rejected
work cannot alter board state, retain claims or invent a handoff. The independent
event fold still checks identity, contiguous events, fences and exact release.

Only two inherited modules change: the operation and parent folds accept private
derived refusal records and require every one to be consumed. Their standalone
public APIs and default behavior remain unchanged. A new module composes all
checks; no existing observation/authorization/recovery API is weakened. A child
refusal does not advance its parent without another procedure phase: the retained
parent can correctly remain running while its child is already rejected.

All 7,056 other inherited project/data files remain byte-identical. The new module
and 29-method test file bring the project closure to 7,060 files. Tests include
all 26 configured fixtures, both refusal cases, rehashed adversaries, a valid
stalled-history demonstration, explicit clock insertion at start/namespace
deadlines, private-handoff consumption and I/O/input-immutability checks. The
data-only retimer rebuilds all references and byte/record accounting; it does not
execute the producer.

Required validation has two disjoint selections: all 38 operation and 34 parent
methods (72), and all 27 observation plus 29 new refusal methods (56). Each keeps
the original 180-second pure deadline and all original harness/evidence limits.
These are 128 distinct selected methods, not a new full748 or inherited136 run.
No runtime/provider/compiler or inherited test changes occur.

The tested profile remains finite immutable simulated GPIO/PWM with retained read
authority. Arbitrary policy failures, full read withdrawal, auxiliary actors,
complete timing/fault coverage, current compiler identity, aggregate storage and
public qualification remain unfinished. Full attestation, physical-measurement,
independent-outcome and qualification flags stay false. No Runtime, database
connection, physical device, MCU/emulator, live inference, public service or
acquired controller executes. No live HMS or adjacent Harness source changes.
Preparation/review is by the primary agent; helpers remain usage-limited. Actual
results will be retained separately.
