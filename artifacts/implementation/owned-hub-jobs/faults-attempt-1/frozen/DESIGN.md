# Owned host CPU jobs: isolated candidate contract

This candidate will execute one installed original CPU artifact through a real owned process. It is separate from HMS simulation, qualification and public runtime mounts. Candidate job execution remains pending parent source review. The root separately ran the original SIGCHLD query helper's six-case/twelve-check control in `helper-check01`; that preserved packet supplies the pinned helper library.

`HostJobs.start(request)` admits a new original key and returns its associated child still blocked at the launch gate. The first `poll(key)` commits release intent and opens the gate, then performs bounded collection/monitoring. `lookup(key)` returns retained history, `cancel(key)` records cancellation intent and signals only current owned handles, and `reconcile(key)` settles historical ambiguity without restarting or signaling a stored PID. Cancel before the first poll closes the gate without releasing work. One job may remain active; at most sixteen original keys are retained. API calls belong to one owner PID/native thread. No background thread is introduced. Polling is a caller service obligation; wall/settlement limits are observed when serviced, not guaranteed real-time deadlines. A trusted pre-exec hook installs CPU/address-space/file/open-FD/core hard limits before interpreter startup under the verified sole-native-thread contract. Limits are per process: the fixed leader and its one computation child do not share aggregate CPU or address-space reservations.

The first artifact computes a sum of squared terms of a typed integer arithmetic progression. Its inputs are `first`, `step`, and `count`; the result is reduced modulo 2^64. A bounded closed-form calculation validates the worker's actual result without repeating its CPU loop. The normal worker forks one computation child and reaps it, making inherited writer settlement a real exercised obligation. Requests contain an original `(deployment, caller, operation)` key, exact installed artifact digest, typed inputs and limits. Requests cannot contain shell commands, executables, paths, modules, code or test modes.

Installation identity pins the original provider/contract/ledger/worker/helper source, the loaded original helper bytes and selected interpreter bytes/version. Source/input bytes are copied into sealed memfds before launch. The child uses `-I -S -B`: global and user site startup are excluded. The dependency scope remains explicit: the host standard library, loader and shared system libraries are trusted dependencies, not a claimed fully pinned or sandboxed runtime. There is no inference/GPU/GB10 readiness claim.

Launch has a durable barrier: admitted → launching with inode-pinned inherited writer lease → child spawned but blocked on a pipe → pidfd acquired while the original child is unreaped → durable association → serviced poll commits release intent → one gate byte. EOF, an unexpected gate byte or bootstrap failure exits without computation or descendant creation. Only the live owner session that created the row can release its gate. Cancellation or any exception before release closes the gate; it never opens it later. A committed release intent is conservatively `mayHaveActed=true`, including a crash before the byte was delivered. Reopen never relaunches that key.

Exact original-key lookup and digest comparison precede fresh installation/source checks. A changed request under a retained key conflicts. A matching historical key returns the prior record even after the current installation changes. This does not authorize a new launch. Historical status, live ownership, cancellation acceptance, output validation and writer settlement are distinct fields.

The owned-session contract requires a single native thread, the same owner PID/thread on every API call, default SIGCHLD disposition, no SA_NOCLDWAIT, and no competing reaper. An original C helper reads `sigaction` to verify the flags rather than relying only on Python's `getsignal`. The helper does not change dispositions. A failed pidfd or waitable-child ownership check closes an unreleased gate and reports unresolved ownership; it does not signal an unverified numeric PID. Live group signaling uses a retained, waitable, unreaped leader anchor. Default pidfd signaling addresses the leader process, not a process group. No Linux-version inference enables newer group-pidfd features.

Polling observes process-group members and stream EOF, retains bounded output, and checks the exact inherited lease inode. The fixed worker and its trusted child retain that flock open-file-description through exit. Completion requires a waitable leader, no observed live group member, lease quiescence, and stream EOF; valid result publication additionally requires successful exit, exact request/launch association and correct typed output. Cancellation accepted is not cancellation confirmed: quiescence must follow. Group membership can change and lease discipline is a trusted installed-code contract; neither is universal descendant containment. Reopened state has no signal authority. A still-held or replaced/missing lease remains unresolved; a free matching lease permits a conservative recovered outcome, never invented successful output.

Control state uses a bounded private two-slot snapshot ledger with a single bounded temporary file, exclusive owner lock, strict canonical JSON/checksum/shape checks and fsync ordering. Both committed slots must validate; corruption is not silently rolled back into a pre-release state. State size and key count are checked before owned writes. Child stdout/stderr are bounded pipes, and children receive no state-directory descriptor. This bounds the trusted implementation's retained logical writes; it does not establish an aggregate filesystem quota, physical allocation guarantee or public storage admission. Failure to commit state poisons further launch authority, and live work must still be settled using retained ownership.

The prepared control slice covers actual success and replay/conflict, simulated source-read drift with historical replay, cancel before/after gate, output overflow, malformed/wrong-associated output, a writer descendant retaining streams while its leader waits, failed pidfd acquisition, signal-disposition refusal, sealed memfd mutation refusal, owner-session mismatch, and orderly checkpoint exceptions followed by retained-handle settlement and reopen. It does not yet qualify a killed owner, force timeout/CPU exhaustion, or execute early-leader-exit/bootstrap-failure modes. Private installed test modes and checkpoint hooks are not caller request fields. [PLAN.md](PLAN.md) distinguishes implemented controls from those gaps and states the outer runner's separate-session containment limit. Root reviews source and the bounded harness before execution.
