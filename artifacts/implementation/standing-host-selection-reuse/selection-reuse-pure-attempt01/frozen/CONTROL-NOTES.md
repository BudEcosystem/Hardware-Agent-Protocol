# Original control scope and limitations

The production change shares artifact construction, typed-domain matching,
endpoint qualification and compiled-record construction. It leaves public
installed_artifact/parse_artifact/compile_artifact/installation_digest signatures
and validation order intact. Only catalog `_compiled` selects the private path.
The private snapshot's constructor still performs full installation validation;
its identity method accepts only its own detached object. No snapshot is stored
on a catalog/policy/producer, returned to callers or passed into a later guard.

The oracle is the exact original standing_pat.py, SHA256
`b1734acbe443501124b2a6965aa9768abd1eb3c3966e57f4945ebc10f801d726`.
It is copied as data and imported only by the future reviewed pure-control
process. Shared supporting modules are unchanged. The same candidate installation
input, including the honest candidate host image digest, goes to both compilers;
there is no comparison against a falsely relabelled original host receipt.

The34 equivalence vectors include literal dict/canonical bytes, three allowed
labels and hardware-resource order; malformed JSON/duplicate fields/size/depth/
negative zero/missing/extra fields paired with invalid installation; bool/float
and label/domain substitutions; invalid slot/driver/capacity/dependency/alias/
epoch; and structurally valid but unqualified boot/incarnation. Dependency tests
recompute topology identity so they reach the missing driver-dependency rule.
Every result compares exact compiled bytes/configuration payload or exception
class/code/text across old public, new public and new private entry paths.

Additional controls prove public validation count5, private count1 and complete
current selection count3; caller/returned artifact and compilation detachment;
wrong stored digest refusal before installation validation; fresh rejection of
changed installation, current configuration constant and installation-validator
helper between independent calls. The installation-helper replacement is a
deliberate pure-control refusal probe restored in finally, not a production
extension point. The call-count hook is observational and does not measure time.

Live management exercises the existing original evaluation/promotion replay,
original-run reassociation refusal and public suspension/re-promotion. Late
evidence withdrawal and controlled stored-artifact corruption occur after
initial selection, before COMMIT; fresh final guards must roll back all new
claims and permit a later clean explicit prepare after restoration. The SQL
corruption is a negative stored-record test, never capacity population or
application evidence.

The six preserved live controls are renewal_withdrawal, expiry_after_commit,
shared_authority, finite_policy_replacement, prepared_mutation_recovery and
common_revoke_remains_unresolved. Their original assertions run against the
candidate assembly. New evidence wrappers add owned identity/reap, full native
snapshots and trace retention; they do not replace the native endpoint. These
are living-owner controls, not new killed-owner qualification.

Source-file mutation on disk, arbitrary runtime monkeypatches during a pure call,
hostile same-user writers and a full Python/native dependency closure are not
established by these controls. Existing source/image checks remain unchanged;
the tested helper/constant changes occur between calls. No performance or
full-capacity result exists yet. The earlier failed capacity attempt is retained
unchanged and is not a pass of this candidate.
