# Reviewed-source execution plan

Status: source-only. Root must review all final sources, deltas and the exact
source inventory before either fixed invocation. Do not execute these commands
as part of source preparation:

```
python3 -I -B run_checks.py pure
python3 -I -B run_checks.py live
```

Run sequentially and stop at the first failure. Each profile creates an exclusive
`selection-reuse-<profile>-attempt01`. A correction requires new reviewed source
and an explicitly selected `--attempt 2` through16; no automatic retry or
overwrite is allowed. All prior receipts remain pinned.

The pure profile has one control case and zero native children. It imports the
exact original compiler source as a fixed oracle under a private module name,
using the unchanged supporting modules and the same candidate installation
input. It compares34 bounded vectors: six valid and28 refusals, including paired
malformed artifact/installation cases. It additionally checks detachment,
current constants/helper replacement between calls and original digest refusal
order. A control-only observational call hook counts installation validation;
it does not replace the JSON parser/encoder or claim timing improvement.

The live profile has nine named cases, each with its own actual original native
pipe peer: management replay/run conflict; late evidence withdrawal; late stored
artifact corruption; and six byte-exact original authority/expiry/shared-claim/
policy-replacement/prepared-recovery/common-revoke controls. Fixture construction
performs actual publication/evaluation/promotion against the original retained
C receipt using the candidate's new host source identity. Each case retains all
28 native selectors, raw original request/reply packets, current route/capacity,
registered child identity and clean EOF exit0. Reopen keeps the same peer and
accumulated trace. Any nonzero native exit fails the case and outer reduction.

One original Guardian owns each control; the control's Guardian owns its native
peers. Kernel-child relationships and live handles supply signaling authority;
stored PIDs do not. The exact original helper/Guardian bytes are reused. Both
profiles retain30-second observed wall/CPU and512MiB address bounds for the
control,5-second CPU/256MiB per native,1MiB FSIZE,64 FDs,core0,3-second TERM grace
and8-second settlement. The inherited observed96MiB/256-state-file monitor is
not reserved disk or an aggregate kernel quota. Final source rehash/cleanup time
is distinct from the control's observed30-second deadline.

The runner verifies the actual held interpreter descriptor, source lengths/hashes,
260 unchanged project/helper/Guardian files, original oracle/provenance copies,
the original host and sealed diagnostic/proposal packets, and public244 before
and after. It pins every frozen input, command, expected case/child count and
actual original native/qualification root. It compiles nothing and invokes no
qualifier. Pending INT/TERM, unexpected children, failed cleanup, changed inputs
or a deferred signal during final publication prevent a passing receipt.

The shared `_compile_record` resolver is one of two fixed pure implementation
helpers: public installation_digest or the private snapshot's identity method.
It executes at the original field-construction point. It is neither a request
argument nor an authority/provider callback. The snapshot is created after the
same artifact-document-first check, and no database, image, policy or evidence
callback occurs while it is reused. Every `_compiled` invocation—including
management and final guards—constructs a new snapshot.

complete the full mutation/episode/activation/key/fixed-writer capacity matrix.
