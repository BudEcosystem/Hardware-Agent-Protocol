# Next work after the hierarchical workload timeout

Preserve the exact candidate, nine passing semantic scopes, failed full writer and
read-only audit. The new hierarchy is useful verified progress, but it has not
passed the required 4,270-file workload. Do not install it publicly, reopen or
repair the failed original image, repeat the same experiment, enlarge its 128 MiB
geometry or extend the original replay limits to turn the timeout into a pass.

Investigate cost before proposing a replacement. Source inspection identifies
multiple durable steps for each new file: reserve an identity, initialize inode
metadata, stage/publish the directory entry, write chunks and publish size/bitmap
updates. The unchanged block provider checks host ownership on every callback.
Those are candidate cost sources, not measured explanations for the deadline.
The 106.587-second CPU receipt alone cannot attribute time to Python checks,
littlefs lookup/allocation, storage synchronization or scheduling.

Define a distinct bounded diagnostic with exact source and operation boundaries,
representative directory/file shapes and explicit substitutions. Separate native
callback work, provider validation and durable host calls without treating any
disabled check or memory-backed run as qualified storage. Do not change checks,
durability and layout simultaneously and then claim a causal speedup. Read the
relevant implementation bodies in full and retain the diagnostic before revising
the demonstrated bottleneck. A new candidate must retain full ownership checks,
uncertain-error poisoning, stable handles, publication/recovery ordering and the
same complete-workload acceptance gate.

The current controls do not cover every mutation interruption. Renames,
replacement, unlinks, final-reference deletion, data metadata commits and recovery
itself still need selected process-interruption qualification for the hierarchical
layout. The previous flat adapter's interruption matrix does not transfer to this
different namespace. Maximum inode count is an admission limit; this stage does
not allocate 8,192 live inodes or establish a full-image capacity envelope.

Even a successful hierarchical replay would leave the complete service gates:
SQLite locking, descriptor behavior and temporary/journal confinement; caps before
recovery writes; hard aggregate accounting for every writer and unlinked object;
separately backed capacity for admitted control continuations; and authority-only
startup/history when bulk is missing or full. Preserve DELETE/EXTRA Journal/vault
durability and the distinct supervisor FULL profile. Missing evidence must not
become novelty, a new operation key, a replacement producer or a repeated effect.

Keep device I/O, driver services and the intelligence hub in the same typed
resource/dependency graph. Known contexts use qualified deterministic PATs with
fresh bindings; unfamiliar contexts invoke the agent. Generic endpoint firmware
and local control loops must support device operation and qualified outage behavior
without depending on model or storage timing. Real providers, persistent MCU
applications, prompt learning, microscopy, Harness installation and the remaining
research/home/lab/manufacturing scope still need implementation and qualification.
