# Import complete I/O evidence for the original admitted run

This stage continues the frozen [execution handoff](../pat-io-execution-handoff/results/README.md). All 253 preceding project files are copied unchanged before implementation. The current worker failures remain retained. No failure is retried, reclassified as success or repaired by an evidence import.

The missing boundary is an authority-owned, serialized evaluation record joining the actual reservation, configuration receipt, supervisor authority, handoff, request, attempt and complete independently inspected output. The current catalog's two-argument evaluator callback cannot express that invocation. Import and historical reading are implemented before adding a versioned catalog invocation and current-environment eligibility contract.

## Producer and consumer identities

The evidence consumer lives in a separate host package. Adding a consumer must not silently change the evaluated producer or require that the worker import its evaluator. The producer's existing ten-source supervisor identity and full worker image stay unchanged. The consumer has its own pinned implementation identity covering its reader, reducer, storage implementation and the semantic inspection dependencies. Neither identity is a hardware-outcome attestation.

The installed consumer receives the actual execution-store object, sharing the existing Journal and its current administrative authorization. Calls name only the evaluator and original run. A caller cannot supply a path, replacement attempt, successful result, callback, archive or trust document to the import entry point. Immutable input and attempt references come from the existing authority stores.

## Read, inspect, publish

1. Resolve the committed handoff and exact original supervisor row under current authority. Existing imports replay their immutable receipt; they do not acquire another worker or rebuild a run.
2. Require a terminal archived attempt with a complete successful worker transport and original request/return association. A failed or unavailable return is retained by its existing supervisor and cannot enter this import profile. The archive's unknown `unresolvedEffects` field is not treated as zero; the independent complete-group inspector must establish the required outcomes.
3. Read the original input and output through bounded, no-follow descriptors anchored at the installed supervisor root. Check the original writer lease identity and quiescence. Validate the exact archive closure against the retained supervisor receipt and bind inputs to the Journal reservation. No stored PID is used to signal a process.
4. Independently inspect the complete declared matrix outside the Journal transaction. Preserve all required cases and original effect, record, byte and time limits. A partial matrix, contradictory outcome, noncanonical document or unknown state cannot be accepted as a passing evaluation. The original captured bytes and derived inspection documents retain separate provenance.
5. Publish the bounded evidence closure, evaluation record and original-run association atomically in the shared Journal. Recheck current authority and the unchanged reservation/handoff/attempt at publication. A rollback publishes nothing; loss of the commit reply resolves the same import. Missing or conflicting retained data is not repaired from the worker directory.

Evidence import is historical. A later configuration or endpoint-session change does not rewrite the imported evaluation. Fresh PAT eligibility must additionally compare the current allowed environment, evaluator configuration and dependencies. The import receipt itself does not activate a catalog entry or authorize device actions.

## Retention and integration

The new profile must declare bounded document counts, actual BLOB sizes, per-run closure size, store capacity and metadata accounting. Validate storage type and size before fetching bodies. Reject missing/extra/shadow schema and inconsistent metadata. Encoded limits do not provide aggregate filesystem enforcement or protected control capacity.

Store publication and lookup must keep the catalog's transaction constraints visible. Complete semantic inspection cannot run under routine admission locks. A later eligibility verifier needs current-byte integrity checks plus an explicitly prepared semantic validation result; a cold or unavailable verifier is an availability refusal, not a novel scene or permission to generate replacement actions.

Required checks include current authorization, replacement supervisor, changed request/return/closure, active or mismatched writer lease, unsafe files, incomplete groups, cross-run substitution, commit interruption, exact replay, source/configuration drift, bounded storage reads and retained corruption without reset. Positive pure-reducer fixtures must be identified as such; mocked association tests cannot establish a real successful handoff worker. Any fresh actual-worker scenario keeps the original complete matrix and original deadlines, even if it fails.

The full target remains prompt-driven applications, deterministic qualified PAT reuse, trace-based learning, persistent Arduino controllers, shared device/driver/hub control, real providers and microscope commissioning. This finite-I/O evidence profile is one integration boundary, not a substitute for those requirements.
