# Microscope controller binding: proposed evidence boundary

This is a source-grounded design for a future HMS microscope adapter. No microscope adapter, controller firmware change, or physical qualification was implemented by this review. No acquired program or test was executed, and no device or running microscope service was contacted. The independent HMS runtime remains a simulation. The mechanical dimensions, loads, travel, required resolution, objective clearance and controller of the intended retrofit are still unknown; this document does not select hardware.

The central rule is to preserve what each observation actually establishes. A submitted command, a controller finishing its command queue, a measured stage displacement, a saved frame and an acceptable focus result are different events. The [reading manifest](../research/microscopy-controller/selected-files.json), [coverage record](../research/microscopy-controller/coverage.json) and [source critique](../research/microscopy-controller/source-notes.md) delimit the evidence behind this proposal.

| Source signal | What the reviewed implementation establishes | Required HMS interpretation |
|---|---|---|
| Sangaboard nonblocking `done.` | Motion was started; the reply is emitted before stepping completes | Command acknowledgement only |
| Sangaboard `moving=false`, `stopped`, `p?` | Firmware motion state and issued-step counters | Controller-reported completion/position, with freshness and boot identity; no inferred encoder measurement |
| Gently `Status` after `waitForDevice` | The configured MMCore adapter finished waiting | Driver completion, qualified by adapter mode and subsequent evidence |
| OpenFlexure `scan_phase=Complete` | Scan lifecycle cleanup completed, including error/cancel paths | Inspect the distinct scan result and motion evidence |
| Captured image plus host timestamp | An image was obtained; the timestamp may bracket host work rather than exposure | Preserve timestamp semantics; do not label it sensor exposure time |
| JPEG-size maximum / focus fit | An algorithm selected a peak from particular frames | An algorithmic focus verdict with metric, samples, configuration and failure state |

These distinctions follow the retained [Sangaboard stage source](../research/microscopy-controller/repos/sangaboard-firmware/src/modules/stage/stage.cpp), [OpenFlexure scan source](../research/microscopy-controller/snapshot/openflexure-microscope-server/src/openflexure_microscope_server/things/smart_scan.py) and [Gently stage wrapper](../research/microscopy-controller/snapshot/gently/gently/hardware/dispim/devices/stage.py).

**Commissioning and authority.** Bind an adapter to an explicit controller identity, serial path, firmware build and axis map. pySangaboard's automatic port discovery sends identification traffic; HMS should not use it to discover an uncommissioned instrument. Admission must bind the immutable operation to the instrument generation, coordinate-frame generation, calibration digest and an exclusive control epoch. A host lock only serializes cooperating callers. The reviewed Sangaboard command path has no operation key, owner epoch, expiration or durable replay result, and Gently deliberately enables its operator joystick at startup. A native controller fence or a demonstrably exclusive gateway is therefore still needed for competing hosts, manual controls and stale queued commands. Same-UID local HMS authorization does not supply controller fencing or distinguish individual agents.

The controller must reject an obsolete ownership epoch before a side effect. A gateway unable to make that guarantee must advertise the weaker scope and refuse unattended operations that require exclusivity. A reboot, USB reconnect, unexpected manual move, origin reset, axis inversion or coupling adjustment invalidates the relevant reference/calibration evidence. Reconciliation must not resend an uncertain relative move. Query the retained operation and controller state; if the device cannot correlate an operation, report the uncertainty and require an explicit recovery procedure.

**Frames, limits and motion.** Keep step counts, rotary motor angle, stage displacement and image coordinates as separate quantities. OpenFlexure's camera-stage mapping maps image `(y,x)` displacements to integer XY motor steps, fits backlash and rejects some poor fits. It does not establish a traceable micrometre scale or a safe Z clearance. Its `calibration_required` check tests for a stored matrix, without tying that matrix to an objective, crop, mounting or current mechanical condition. A proposed calibration record needs those identities, fit residuals, uncertainty, validity region and reference evidence. Zeroing a counter is a coordinate change; homing needs an independently qualified reference event. See the [mapping implementation](../research/microscopy-controller/snapshot/openflexure-microscope-server/src/openflexure_microscope_server/things/camera_stage_mapping.py).

Validate the complete swept path, including backlash take-up, calibration probes, autofocus recentering and any return move. OpenFlexure can introduce compensation movement on axes that had no requested net displacement. Its motion-detection calibration doubles probe sizes up to 16,384 steps; the cumulative probe distance and subsequent measuring traversals need an explicit physical envelope. Gently's measured overshoot margins and fixed XY numbers belong to its particular rig and must not become retrofit defaults.

For ASI, commission against the actual card, firmware and Micro-Manager adapter. The official [STATUS reference](https://docs.asiimaging.com/commands/status) defines busy in terms of serial-command motion; [RDSTAT](https://docs.asiimaging.com/commands/rdstat) exposes additional axis state. The [ASITiger adapter documentation](https://micro-manager.org/ASITiger) also warns that armed fast sequencing short-circuits `Busy()`. Consequently, a completed wait is insufficient evidence of stationary mechanics across all controller modes. Soft-limit readback, trigger/sequence state, manual-input state and fresh position evidence need to be considered together. No mechanical stopping distance was measured here.

**Cancel, stop and park.** Define three separate actions: stop producing new scan/acquisition work; stop commanded motion and assess quiescence; and execute an explicitly authorized park trajectory. OpenFlexure catches scan cancellation and normally returns to the starting position with cancellation blocked, then may stitch. Its calibration cleanup similarly returns to the start. Wrapping these actions as an immediate stationary stop would misstate their behavior. Error cleanup can also start return motion. An HMS adapter must either suppress that behavior through an appropriate upstream seam or admit and reserve the entire cleanup trajectory in advance; a transport cancellation alone does neither.

Stop admission must be independent of a blocked normal command. The reviewed pySangaboard queries use a communications lock and normally allow an unbounded serial read. The firmware's optional endstop homing state machine advances when motion becomes idle; `stage_stop` does not clear those homing flags. Source inspection therefore identifies a possible next homing move after stop. Endstops are disabled in the reviewed default configuration, and this concern was not reproduced on hardware. It is a qualification blocker for claiming a bounded homing abort, not a claim about every shipped Sangaboard. A future endpoint needs stop semantics for every motion mode, a local expiry/deadman mechanism, latched fault reporting and independently checked residual motion.

**Images and focus.** Use a frame identity and content digest, immutable capture configuration, raw sensor metadata, clock identity/boot epoch, host receipt interval and the pose evidence applicable to the exposure. The [Picamera2 manual](https://datasheets.raspberrypi.com/camera/picamera2-manual.pdf), release 7, provides a completed-request API that couples pixels with their metadata. Its documented `SensorTimestamp` is first-pixel readout time on the boot-relative clock; exposure duration must be accounted for when deriving exposure start. `flush` can select a request whose first-pixel exposure begins after a stated instant. This still needs sensor-specific rolling-shutter/readout treatment and a qualified mapping to the motion clock. It does not by itself prove the whole frame was exposed at a settled pose.

OpenFlexure's autofocus interpolates Z from host wall-clock endpoints of a move; it does not sample an encoder trajectory. A smart-stack high-resolution image and its subsequent low-resolution JPEG-size measurement need separate frame identities unless explicitly acquired together. Gently's reviewed camera and volume timestamps are host completion timestamps. Failed reads must remain failed; Gently's Z wrapper substitutes zero on some errors, and its nudge helper can log a move failure then return a success response. An HMS adapter must not promote those values into valid position evidence. See the retained [camera](../research/microscopy-controller/snapshot/openflexure-microscope-server/src/openflexure_microscope_server/things/camera/picamera.py), [autofocus](../research/microscopy-controller/snapshot/openflexure-microscope-server/src/openflexure_microscope_server/things/autofocus.py) and [Gently device-layer](../research/microscopy-controller/snapshot/gently/gently/hardware/dispim/device_layer.py) sources.

Autofocus admission should fix the absolute travel envelope, time budget, number of attempts, capture/exposure budget, metric implementation, image configuration and acceptance rule. Keep the raw curves, selected frames and rejected reasons. A flat curve, boundary peak, saturation, sparse sample, malformed image, missing frame or stale pose can produce an inconclusive result. The [OpenFlexure autofocus paper](https://arxiv.org/abs/2109.06842v2) supplies useful counterexamples: JPEG size can favor defocus on sparse features, while image artifacts can dominate a Laplacian metric. Its reported stack-centering result is tied to its specimens and apparatus; it does not qualify this proposed retrofit or provide a universal confidence score.

**Completion and qualification.** A future operation should retain separate command acceptance, controller terminal state, measured final pose, acquisition completeness and image/focus-quality verdicts. Require expected frame counts and explicit dropped/duplicate frame accounting. Attempt each critical cleanup independently and preserve its result; the reviewed Gently volume cleanup can skip later laser-off work if an earlier reset throws. Neither a timeout nor a returned image should clear uncertainty about ongoing motion or illumination.

Before a physical binding can claim these properties, qualify controller reset during motion, lost acknowledgement, repeated immutable intent, stale ownership epochs, direct/manual override, all homing stop phases, stuck limit inputs, lost steps/slip, backlog and blocked-serial stop latency, compensation near boundaries, clock discontinuities, missing camera metadata, incomplete stacks and cleanup failures. Then measure repeatability, calibrated displacement, settling and focus behavior over the actual load and optical configuration. The tests inspected in this review are source evidence for software behavior; none was run, and none substitutes for those measurements.
