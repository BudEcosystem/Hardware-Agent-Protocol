Often an SDK release has fixed some such bugs whilst introducing new ones. The code has been thoroughly re-vetted, somewhat simplified, and even more exhaustive tests added.  \r\n\r\nSome synchronization primitives on RP2350 also suffered from busy-wait instead of sleep issues in `pico_sync` which were related to the above, and so these issues have also been fixed, with new tests added.\r\n\r\nFinally, the interoperability of synchronization primitives with FreeRTOS tasks has also had more exhaustive tests added, and some _preexisting_ rare race-conditions were identified that will need to be fixed in the FreeRTOS RP2040/RP2350 ports.\r\n\r\nNote that `PICO_SPIN_LOCK_UNLOCK_CAUSES_SEV` has been renamed to the more accurate `PICO_EXCLUSIVE_ACCESS_SETS_OWN_EVENT`.\r\n\r\nThe following defines were added:\r\n\r\n* `PICO_SYNC_EXCLUSIVE_ACCESS_EVENT_WORKAROUND` which indicates whether spin lock based synchronization primitives relying on processor events (`__wfe()`) for notification need code to workaround exclusive accesses setting the processor's own event, and defaults to\r\n`PICO_USE_SW_SPIN_LOCKS && PICO_EXCLUSIVE_ACCESS_SETS_OWN_EVENT` (i.e. 1 if on RP2350 and not using hardware spin locks, 0 otherwise).\r\n\r\nFor RTOS integration, the following defines were added:\r\n\r\n* `PICO_TIME_USE_SLEEP_NOTIFIER` which defaults to 1 if any of the `lock_internal_` defines are overridden (0 otherwise). This should be set to 1 to keep the prior SDK behavior of routing SDK sleeps thru `lock_internal_spin_lock`/`lock_internal_spin_unlock_with_wait()` when integration with an RTOS to prevent an RTOS task in an SDK sleep from hogging its core.\r\n* `LOCK_INTERNAL_SPIN_UNLOCK_WITH_NOTIFY_WAKES_ALL` which defaults to 0  if any of the `lock_internal_` defines are overridden (1 otherwise). The original contract in `lock_core.h` intended that all RTOS implementations of `lock_internal_spin_unlock_with_notify()` should wake _all_ existing waiters, but the existing FreeRTOS ports actually do not do so correctly in all circumstances. An RTOS integration which does abide by the contract should set `LOCK_INTERNAL_SPIN_UNLOCK_WITH_NOTIFY_WAKES_ALL=1` to suppress the new SDK workaround which generates additional wake-ups when a waking primitive does not acquire exclusive access to a resource (i.e. additional waiters may proceed) \r\n\r\n#### hardware_exception\r\n\r\n* Fixed debugger stack trace for unhandled exception on RISC-V.\r\n \r\n#### hardware_irq\r\n\r\n* Added `irq_is_pending()` to determine if an external system IRQ line is currently asserted, or if\r\nthe IRQ has been forced high using `irq_set_pending()`.\r\n\r\n#### hardware_pio\r\n\r\n* Fixed a release-build-only `pio_encode_mov()` bug.\r\n\r\n#### hardware_xosc\r\n\r\n* Add `PICO_XOSC_FREQ_RANGE_MAX` configuration (not available on RP2040).\r\n\r\n#### pico_async_context\r\n\r\n* Fixed initialization under FreeRTOS SMP to pin the worker task to the caller's core at creation rather than shortly after, to prevent it from briefly running on the wrong core.\r\n\r\n#### pico_cyw43_arch\r\n\r\n* Fixed `cyw43_arch_deinit()` followed by a fresh `cyw43_arch_init()` under FreeRTOS when using lwIP.\r\n\r\n#### pico_low_power\r\n\r\n* On RP2350, clean up correctly after a timed dormanncy (`low_power_dormant_for_ms`/`low_power_dormant_until_aon_timer`).\r\n\r\n#### pico_mbedtls\r\n\r\n* Added missing `psa_crypto_random.c` to pico_mbedtls_crypto.\r\n\r\n#### pico_platform\r\n\r\n* `__time_critical_func` was modified in SDK 2.3.0 to add `__no_inline`, and this change has been reverted. A `__no_inline_time_critical_func` has however been added to match the `__not_in_flash_func`/`__no_inline_not_in_flash_func` pair. TLDR: Whilst explicitly setting a `__time_critical_func` to be inline makes no sense since the entire point is to place the outlined function somwhere, it is possible that existing code does make nested calls amongst `__time_critical` functions in a way that the compiler might choose to inline, meaning that the addition of a forced outline call in this case (in SDK 2.3.0) may have changed timing/behavior that was relied upon for time critical code. \r\n* `PICO_PLATFORM_STRING` is now initialized to the stringified value of `PICO_PLATFORM` by the CMake build. It defaults to \"unknown\" if not set by the build.\r\n\r\n#### BTStack\r\n\r\nUpdated BTStack to `eb0bb8b5e` from 1.8.2 (included in SDK 2.3.0):\r\n\r\n* Fixes a regression that made cyw43 behave as a synchronous transport, which could cause hci_run to not be invoked. BlueKitchen has reworked the logic to work properly.\r\n* Fixes a long-standing issue affecting bonding with BR/EDR to LE Cross-Transport Key Derivation where the key could be reversed.\r\n\r\n#### TinyUSB\r\n\r\n* TinyUSB is not updated in this release (it is intended to be in 2.3.2), however a few minor changes were made to support the latest upstream TinyUSB, which may be used by cloning it and setting `PICO_TINYUSB_PATH` (or by updating the submodule in `lib/tinyusb`).\r\n\r\n### Miscellaneous\r\n\r\n* Numerous documentation corrections/improvements.\r\n\r\n### Build\r\n\r\n* GCC 15.3.1 is now supported.\r\n* [Arm Toolchain for Embedded 22.1.0](https://github.com/arm/arm-toolchain/releases/tag/release-22.1.0-ATfE) is now supported.\r\n* Fixed an issue where some build types (e.g. Arm GCC without debug info) would pull 40 KiB of library code into RAM.\r\n* Fixed the RISC-V compiler selection to correctly pick the compiler with the most up-to-date extension support.\r\n* Now include `.got` sections in the binary explicitly.\r\n* Added `-ftls-model=local-exec` to all builds.\r\n* Added `-mstrict-align` to RISC-V builds by default; may be disabled via `PICO_NO_STRICT_ALIGN=1`.\r\n* Setting `PICO_HARD_FLOAT_ABI=1` no longer causes an error on RP2040.
