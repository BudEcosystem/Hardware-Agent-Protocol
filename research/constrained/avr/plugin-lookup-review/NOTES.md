# GCC 7.3 plugin lookup diagnosis

The failed LTO attempt used the wrong lookup contract. Upstream GCC 7.3 `-print-file-name=NAME` calls `find_file`, which searches `startfile_prefixes` with `R_OK` and multilib traversal enabled. Failure returns the unchanged name. That exactly explains the retained bare `liblto_plugin.so` result without establishing that the linker plugin is absent.

Actual GCC-driver linking selects `LTOPLUGINSONAME` with `find_a_file(&exec_prefixes, ..., R_OK, false)`. Program-name queries also use executable prefixes, but use `X_OK`, so they are not an equivalent plugin check. `access_check` excludes directories only for `X_OK`; an `R_OK` model must not silently skip a readable directory or another unexpected readable winner.

The `programs: =...` line of `-print-search-dirs` is built from `exec_prefixes` with `check_dir=false` and `do_multi=false`. Both this output and actual plugin lookup traverse the same complete `for_each_path` implementation. The output preserves ordered prefixes, including nonexistent directories. For each prefix, plugin lookup appends the basename directly, uses `access(..., R_OK)` and stops at the first readable candidate. No executable suffix is appended for this mode.

`LINK_PLUGIN_SPEC` inserts the selected path as `-plugin %(linker_plugin_file)` into the link command. The complete `collect2` main function was read: it recognizes `-plugin`, sets `use_plugin`, disables its separate non-plugin LTO path, and forwards the plugin argument through its ordinary linker argument construction. It does not perform the original plugin-file search itself. This review does not qualify every downstream linker or plugin-loading function.

The corrected isolated runner therefore proposes one same-profile, same-environment `-print-search-dirs` query, a bounded exact three-line parser, and ordered first-readable `R_OK` selection. The first readable candidate must satisfy the existing archive/path/alias pins and resolve to the already declared plugin. An unexpected winner is a refusal, never an invitation to search later entries. The selected order and readable states through the winner are rechecked before/after later commands and in the final audit. This preserves the current before/after observation scope; it does not make the filesystem immutable.
