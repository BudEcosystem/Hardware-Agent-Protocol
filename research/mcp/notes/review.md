# MCP mapping decisions and unresolved scope

The 2026-07-28 base, versioning, stdio, tools, discovery, patterns, cancellation, caching and pagination pages were read in full at the pinned commit. The earlier 2025-11-25 lifecycle, tools, cancellation and ping pages were also read, with selected legacy stdio text. Exact coverage is in the adjacent receipt.

The current protocol carries version and client capabilities on every request, uses `server/discover`, requires `resultType`, and gives list/discovery results cache hints. The older protocol uses `initialize` and `notifications/initialized`. HMS supports these two explicitly; optional client identity is display data, not authorization. The adapter never requests client sampling, filesystem roots, elicitation or credentials. Its fixed tool list is independent of conversation or prior device discovery. Device authorization remains at the local daemon's POSIX principal boundary.

MCP request IDs correlate delivery; HMS operation IDs and retained immutable requests identify physical intent. The stdio unexpected-termination text suggests retrying lost requests. That transport-level guidance does not establish exactly-once side effects. HMS therefore never automatically resubmits a mutation or changes its operation key. A new JSON-RPC request may deliberately carry the identical retained HMS invocation within its valid replay namespace; expiration requires reconciliation rather than reconstructed intent.

Cancellation abandons an in-flight MCP reply. It cannot infer whether the local daemon already admitted an operation, whether a controller started, or whether a plant stopped. The implementation suppresses uncommitted canceled replies while retaining bounded worker occupancy until the one local call returns. Only an explicit `hardware_cancel` tool requests domain cancellation. A response already committed to the output queue can win the delivery/cancellation race. A transport failure leaves mutations unconfirmed.

Every tool declares input and output schemas derived from the checked local API, with local reference closure. Structured replies and text JSON contain identical data. Error replies are included in the output union and carry `isError`; unknown tools and malformed MCP envelopes instead use protocol errors. Native host bounds and semantic correlations are stricter than JSON Schema alone. These schemas do not establish physical truth.

The static tool catalog has private cache scope and a 60-second hint. This never becomes an observation-age guarantee or authority cache. Actual device observations and admission revalidate their own host contracts. Unknown continuation state, unadvertised task support, and arbitrary extra tool-call fields are rejected; no MRTR continuation can silently perform additional effects.

Several source inconsistencies are retained. The current index still describes extension negotiation during initialization, whereas its normative base/versioning chapters remove that handshake. The cancellation page requires a server cancellation notification when it tears down a subscription, while the subscription page recommends a graceful completion response. This profile acknowledges an empty supported filter and holds the bounded subscription until client cancellation or transport shutdown; it implements no spontaneous subscription teardown policy. The TypeScript InvalidParams commentary includes tool-argument validation, while the Tools chapter recommends reporting actionable input failures as tool errors. HMS follows the latter distinction and validates the generated output union.

The current installed SDK is 1.26.0 and advertises 2025-11-25. Its presence is not current-version compatibility evidence. The original modern wire tests validate selected result structures against the retained official generated schema, and legacy SDK compatibility is tested separately. Neither proves compatibility with every client or compliance with unimplemented HTTP, authorization, task, resource, prompt, logging, sampling or UI extensions. The implementation is a local simulation projection, not a remotely commissioned hardware service.
